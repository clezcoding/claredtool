# Phase 04.1: Stitch→React 5-route conversion - Context

**Gathered:** 2026-08-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Convert approved Google Stitch HTML for the v1 5-item nav (Rechnung · Entities · Kunden · Tax · PDF) into production TSX/React in the Tauri desktop app using the **stitch-build** plugin skills (`react-components`, `shadcn-ui` where patterns match, `react-vite-dashboard` patterns as fits). Extract shared AppShell once; close P1 backlog R-01–R-04 as superseded or fixed per decisions below; meet conversion acceptance in `.stitch/qa/STITCH-APPROVAL-BACKLOG.md`.

Out of v1 nav / Phase 5.1: login, onboarding, dashboard, catalog, banking, settings, splash, full command palette, and other D-13 screens — except where this phase explicitly pulled artifacts in (09-empty, 15-export with PDF).

<decisions>
## Implementation Decisions

### Conversion waves (stitch-build)
- **D-01:** Wave order: shared **AppShell first** (R-01/R-02), then routes one at a time — not big-bang. — **Reversibility:** reversible
- **D-02:** First content route after shell: **Rechnung** (02/03 densest, core loop).
- **D-03:** Reuse local approved `.stitch/designs/*` HTML/PNG; MCP `get_screen` + `fetch-stitch.sh` only when a screen is missing or broken (skill Phase 1 gate still applies for any refresh).
- **D-04:** Entities + Kunden: extract **one Shared List+Panel** from 04/05, then wire both (incl. 18-kunden-list). — **Reversibility:** costly — shared module touches two routes

### Tokens, theme, fidelity
- **D-05:** Take Stitch classes/hex/spacing **1:1** into TSX (not remap-first to Phase 4 CSS vars).
- **D-06:** When Stitch values **diverge** from Crafted Minimal D-02 CSS vars: **Stitch wins**; sync CSS vars afterward to match Stitch. — **Reversibility:** costly — token SSOT shifts toward Stitch for converted surfaces
- **D-07:** Single component tree + `dark:` variants; OS-follow theme (Phase 4 D-06); light/dark PNGs are QA references only.
- **D-08:** Visual SSOT for conversion: **side-by-side** Stitch HTML/PNG **and** `mockups/approved/` 02–07.
- **D-09:** Aim for **pixel-match inside Phase 4.1**; Phase 6 = true residuals after auto-diff + end UAT. — **Reversibility:** costly — expands 4.1; shrinks Phase 6

### Overlays, empty, P3 interaction
- **D-10:** Convert Screen→Route map **“Also relevant”** modals with their routes (23, 24, 26, 27, 29, 39, …).
- **D-11:** Convert **both** `37-empty-entities` and `09-empty-state` in 4.1 (09 is an explicit scope bump vs D-13).
- **D-12:** Include **15-export** with the PDF route (map wins over D-13 “out of nav” listing for this artifact).
- **D-13:** P3 inert HTML (dropdowns, accordion, tabs 45/46, etc.): implement as **real React interaction**, not visual no-ops.

### Data, skill gates, nav wiring
- **D-14:** Keep existing **live API/hooks** (Phase 3); `mockData` only for decorative Stitch copy with no API. — **Reversibility:** reversible
- **D-15:** After each route wave: stitch-build **validate** + `tsc` gate (skill Phase 4 checks locked as required for this phase).
- **D-16:** Use **shadcn** primitives from `packages/ui` where patterns match (Button, Dialog, Input, …); remaining markup = modular Stitch→TSX — no full shadcn rewrite and no ignore-shadcn.
- **D-17:** Nav active state: React Router **`NavLink`** + `className={({ isActive }) => …}` on existing `createHashRouter` / `AppShell`.

### Sidebar (R-01)
- **D-18:** Shared AppShell width = **one Stitch-consistent width**, measured from **`02-rechnung-light`**, normalized across all routes — **not** backlog ~260px.
- **D-19:** Backlog **R-01 closed as superseded** (Stitch SSOT + pixel-4.1). Document in STITCH-APPROVAL-BACKLOG.

### Pixel acceptance & harness
- **D-20:** Release gate: **automated** screenshot diff (pixelmatch-style harness — none in repo yet; planner specifies).
- **D-21:** Tolerance: **byte-equal** PNGs. Planner must pin capture host OS/viewport/scale (D-03 system fonts + native titlebar make cross-host byte equality fail).
- **D-22:** Approval artifact: PASS/FAIL QA note per route (backlog or `04.1` QA file) + date.
- **D-23:** Human UAT: **once at phase end** for all five routes (not per-wave).
- **D-24:** Diff primary: **Tauri window screenshot vs `mockups/approved/` 02–07**; Stitch PNG secondary on disputes.
- **D-25:** Diff both **light and dark** where pairs exist (02/03, 04/05); Tax/PDF per available approved assets.
- **D-26:** Baseline: pinned **Mac** host; golden/approved refs; fixed window size from metadata/aspect.

### F-gap boundary
- **D-27:** Close **F-01–F-09 all in Phase 4.1** (high and medium). — **Reversibility:** costly — Phase 6 becomes residual-only
- **D-28:** Pass-2 extras (full ⌘K palette, heavy filter demo, 12-entity demo volume): **residual / Phase 5.1**; still do P3 interactions where UI chrome exists.

### Empty states
- **D-29:** `09-empty-state` → shared **`EmptyState`** component; routes mount it on empty dataset.
- **D-30:** `37` = Entities-specific empty (copy/CTA); `09` = generic fallback pattern.
- **D-31:** Empty triggers = **real** empty API/store states (optional Dev flag only); no always-on fake empty.

### Persona (R-02)
- **D-32:** Shell persona from **`/me` when logged in**; else canon **Alexander Wagner / aw@clared.de / Greenfield Studio GmbH**.
- **D-33:** On conversion, replace all Stitch demo personas with R-02 canon (or live `/me`).
- **D-34:** Pixel/CI golden uses **R-02 fallback** (deterministic) — not live user names.

### Modal UX
- **D-35:** Open overlays via **local React state** (existing app pattern).
- **D-36:** Browser Back does **not** dismiss modals; Escape / Close (shadcn Dialog).
- **D-37:** No create-modal deep links in 4.1.

### Tax / PDF / export depth
- **D-38:** Tax route: Stitch UI for F-05 **and** keep/wire existing live tax hooks (`tax-live-store` / decisions).
- **D-39:** PDF route: Stitch viewer shell for F-06; generate/download/persist hardness stays **Phase 5**; reuse preview hooks if present.
- **D-40:** 15-export: Stitch UI now; action stub or existing hook; full export jobs → Phase 5 / 5.1.

### i18n
- **D-41:** Introduce **`i18next` + `react-i18next`** in 4.1 with bundled `de`/`en` JSON; **`fallbackLng: 'de'`** (D-15). No HTTP backend required for Tauri. — **Reversibility:** costly — new dependency + string extraction across five routes
- **D-42:** Full app i18n for all five routes (not PDF-only map).
- **D-43:** Fix Stitch EN chrome leaks to German immediately on conversion (e.g. R-10-class copy).

### Icons
- **D-44:** New Stitch surfaces use **Material Symbols** (from Stitch), not Lucide. — **Reversibility:** costly — dual icon systems until lucide touch-points migrate
- **D-45:** Missing Material glyph → nearest Material Symbol + QA note.
- **D-46:** Decorative icons `aria-hidden`; meaningful icons get DE `aria-label` via i18n.
- **D-47:** Existing Lucide usage may remain until those files are touched; new Stitch work = Material.

### Component placement
- **D-48:** New Stitch building blocks → `apps/desktop/src/components/`; pages stay under `apps/desktop/src/routes/`.
- **D-49:** shadcn primitives stay in `packages/ui` (`components.json`).
- **D-50:** Shared List+Panel = one module under `apps/desktop/src/components/` (extend/replace `registry-list-panel` as planner sees fit).

### Shell chrome F-01
- **D-51:** Render ⌘K hint chrome 1:1 for pixel F-01; action **disabled** + “Bald” toast/tooltip; full command palette → Phase 5.1.
- **D-52:** ⌘/Ctrl+K intercept → same “Bald” feedback (no silent no-op).
- **D-53:** Build logo mark + upgrade card with shell in 4.1; upgrade CTA may stub.

### Claude's Discretion
- Exact px measured from `02-rechnung-light` for D-18.
- pixelmatch harness layout, golden capture script, and QA note file path under `.stitch/qa/` or phase dir.
- Mapping table Material Symbol ↔ Stitch ligature names.
- How far to stub upgrade CTA and export actions while keeping pixel chrome.

</decisions>
