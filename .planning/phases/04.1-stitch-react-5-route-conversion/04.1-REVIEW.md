# Phase 04.1: Code Review Report

**Reviewed:** 2026-08-28T00:14:00Z  
**Depth:** standard  
**Files Reviewed:** 44  
**Status:** issues_found

## Summary

Phase 04.1 delivers the five-route Stitch React shell, shared list/detail panels, tax/PDF surfaces, and a Mac pixel-capture harness. Structure and test coverage are solid for a conversion milestone, but three correctness gaps should be fixed before treating the phase as shippable: `stitch:validate` is tied to one developer machine path, entity/kunden detail panels cannot stay closed, and invoice date helpers use UTC `toISOString()` slices that drift from local calendar days. Several stub flows (delete invoice, tax-rule modal save) mislead users without performing the advertised action.

## Critical Issues

### CR-01: `stitch:validate` hardcodes a developer-local absolute path

**File:** `apps/desktop/scripts/stitch-validate.mjs:6-7`  
**Issue:** `VALIDATE` points at `/Users/puzzless/.cursor/plugins/cache/.../validate.js`. On any other machine, CI agent, or after cache eviction, `pnpm stitch:validate` fails with "File not found" even when the component path is valid. The script is wired in `package.json` as the official Stitch gate.  
**Fix:**

```javascript
import { createRequire } from "node:module";
import { existsSync } from "node:fs";

const require = createRequire(import.meta.url);
const candidates = [
  process.env.STITCH_VALIDATE,
  // resolve from installed stitch skill package if published
].filter(Boolean);

const VALIDATE = candidates.find((p) => existsSync(p));
if (!VALIDATE) {
  process.stderr.write(
    "Set STITCH_VALIDATE to validate.js or install the Stitch react-components skill.\n",
  );
  process.exit(1);
}
```

### CR-02: Detail panel close is immediately undone by auto-select `useEffect`

**File:** `apps/desktop/src/routes/entities.tsx:108-114`, `apps/desktop/src/routes/kunden.tsx:127-133`  
**Issue:** `closePanel()` sets `panelMode` to `"none"` and `selectedId` to `null`, but the `useEffect` re-runs on those changes and, when rows exist, forces `selectedId` back to the first row and `panelMode` to `"detail"`. The close button in `registry-list-panel.tsx` (line 465) is wired to `onClosePanel` but has no lasting effect whenever the list is non-empty.  
**Fix:** Only auto-select on initial load, not after an explicit close. Track intent with a ref or guard:

```typescript
const userClosedRef = useRef(false);

function closePanel() {
  userClosedRef.current = true;
  setPanelMode("none");
  setSelectedId(null);
}

useEffect(() => {
  if (loading || rows.length === 0 || userClosedRef.current) return;
  if (selectedId == null || !rows.some((row) => row.id === selectedId)) {
    setSelectedId(rows[0].id);
    setPanelMode("detail");
  }
}, [loading, rows, selectedId]);
```

Reset `userClosedRef` when the user selects a row again.

### CR-03: Invoice date helpers use UTC `toISOString()` for local calendar fields

**File:** `apps/desktop/src/routes/rechnung.tsx:111-125`, `apps/desktop/src/routes/rechnung.tsx:127-131`  
**Issue:** `todayIso()`, `addDaysIso()`, `dueDateFromTerms()`, and `shiftMonth()` all end with `date.toISOString().slice(0, 10)`. `toISOString()` is UTC. For CET users in the early morning (or any non-UTC zone near midnight), "today" and month-shift results can be off by one day relative to the UI date inputs and payment terms. Default `datum` / `faellig` on new drafts inherit the wrong values.  
**Fix:** Format in local calendar space:

```typescript
function formatIsoLocal(date: Date): string {
  const y = date.getFullYear();
  const m = String(date.getMonth() + 1).padStart(2, "0");
  const d = String(date.getDate()).padStart(2, "0");
  return `${y}-${m}-${d}`;
}

function todayIso(): string {
  return formatIsoLocal(new Date());
}
```

Apply the same helper in `addDaysIso`, `dueDateFromTerms`, and `shiftMonth` instead of `toISOString().slice(0, 10)`.

## Warnings

### WR-01: Delete-invoice confirm does not delete

**File:** `apps/desktop/src/routes/rechnung.tsx:1271-1283`  
**Issue:** `AlertDialogAction` only calls `setDeleteOpen(false)`. The destructive affordance (toolbar delete, menu delete, confirm "Löschen") implies removal; the draft remains in state and on the server.  
**Fix:** Wire `onClick` to `apiFetch(\`/api/invoices/${draftId}\`, { method: "DELETE" })`, update `drafts` state, and navigate to the next draft or empty hero on success.

### WR-02: Duplicated tax-percent logic in Rechnung vs shared `money.ts`

**File:** `apps/desktop/src/routes/rechnung.tsx:613-614`  
**Issue:** Line-item USt column recomputes percent inline while `TaxRail` uses `taxFraction` / `taxPercent` from `lib/money.ts` (fixed in `tax-rail.test.tsx` for rate `20`). Divergence risks line items showing a different percent than the rail after a future money-helper change.  
**Fix:** `import { taxPercent } from "../lib/money"` and pass `taxPercent(railTax?.invoice_tax_rate ?? 0)` to `LineItemCard`.

### WR-03: Permission-denied and PDF error retries are no-ops

**File:** `apps/desktop/src/routes/rechnung.tsx:575-579`, `apps/desktop/src/routes/pdf.tsx:133-136`  
**Issue:** `ErrorState` renders a retry button whose handler is `() => undefined`. Users get a recovery affordance that does nothing.  
**Fix:** Hide retry when no handler exists, or pass real reload callbacks (`loadDrafts`, `demoState` reset / refetch).

### WR-04: Kunden create form can POST without `entityId`

**File:** `apps/desktop/src/routes/kunden.tsx:145-158`, `apps/desktop/src/routes/kunden.tsx:315-321`  
**Issue:** Entity combobox has no `required` validation; `handleCreate` always includes `entityId` from form state, which defaults to `""`. Submit can reach the API with an empty entity reference.  
**Fix:** Guard `if (!createForm.entityId) { setFieldError(...); return; }` before `apiFetch`, and disable submit until entity is chosen.

### WR-05: Signed-in shell footer always shows R-02 company string

**File:** `apps/desktop/src/components/app-shell.tsx:49-51`, `apps/desktop/src/components/app-shell.tsx:132-137`  
**Issue:** When `me` is present, `personaCompany` is always `t("persona.company")` ("Greenfield Studio GmbH"), not session data. Live users see a fictional company under their real email.  
**Fix:** Omit the company line when `me` is set, or source company from `me` / org profile when available.

### WR-06: Tax rule modal save discards all edits

**File:** `apps/desktop/src/routes/tax.tsx:744-750`  
**Issue:** Modal "Regel speichern" calls `showBald()` and closes; draft fields never merge into `rules` state. Edit/create modal is visually complete but functionally disconnected.  
**Fix:** On save, map `draft` into `setRules` for create/edit modes before closing; keep `showBald` only for unimplemented sub-actions.
