## Warnings

### WR-01: `dueDateFromTerms` still parses ISO dates as UTC

**File:** `apps/desktop/src/routes/rechnung.tsx:119-122`  
**Issue:** CR-03 fixed local *output* via `formatIsoLocal`, but `dueDateFromTerms` still constructs the base date with `new Date(isoDate)` (date-only form parses as UTC per ES spec). `shiftMonth` and the calendar helpers correctly use ``new Date(`${iso}T00:00:00`)`` (local). Payment-term due dates (`faellig` when terms change) can be off by one day in timezones west of UTC. Low risk for CET-primary users but inconsistent with the CR-03 intent.  
**Fix:**

```typescript
function dueDateFromTerms(isoDate: string, days: number): string {
  const date = new Date(`${isoDate.slice(0, 10)}T00:00:00`);
  date.setDate(date.getDate() + days);
  return formatIsoLocal(date);
}
```

### WR-02: Delete-invoice failure is silent

**File:** `apps/desktop/src/routes/rechnung.tsx:619-621`  
**Issue:** `handleDeleteInvoice` catches all errors and only calls `setDeleteOpen(false)`. On API failure the invoice remains, the dialog closes, and the user receives no error feedback.  
**Fix:** On `!res.ok` or catch, keep the dialog open (or show toast/banner) and surface `t("invoice.deleteFailed")` instead of closing silently.

### WR-03: Post-delete navigation ignores `updatedAt` sort

**File:** `apps/desktop/src/routes/rechnung.tsx:586-617`  
**Issue:** After a successful delete, `applyInvoice(remaining[0], entities)` picks the first element of the filtered array. Elsewhere (`rechnung.tsx:468-470`) drafts are sorted by `updatedAt` descending after save. If the drafts list was not recently sorted, the user may land on an arbitrary draft instead of the most recently edited one.  
**Fix:**

```typescript
const next =
  [...remaining].sort(
    (a, b) => new Date(b.updatedAt).getTime() - new Date(a.updatedAt).getTime(),
  )[0];
if (next) applyInvoice(next, entities);
```
