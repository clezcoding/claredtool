# Phase 04.2: Desktop Platform Hardening - Context

**Gathered:** 2026-08-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Harden the Tauri desktop shell for ship-readiness and premium macOS/Windows feel: observability (log + Sentry EU), auto-update (FaynoSync + updater/process), native polish (prevent-default, store, window-state, notification, dragout smoke, link guard, selection/overscroll), clipboard (one official plugin), and debug-only DX (rich Cmd+D panel, DevTools).

**In scope:** ROADMAP Phase 04.2 Waves 1–5 (desktop feel, observability, ship, DX, clipboard) within stated constraints.

**Out of scope:** tauri-ui scaffold migration; changing MCP bridge policy; Gotenberg / SQL / dialog / fs (Phase 04.3); full PDF product flows / offline sync / audit UI (Phase 5); Settings route; Specta/TauRPC; GlitchTip; OS code-signing (Apple/Windows) — deferred after updater crypto.

</domain>

<decisions>
## Implementation Decisions

### Clipboard
- **D-01:** Use official `tauri-plugin-clipboard-manager` only — not CrossCopy. — **Reversibility:** costly — plugin choice and call sites.
- **D-02:** Ship thin helper API plus 1–2 real copy actions where UI already exists (e.g. invoice number / tax rule id); broader copy UX → Phase 5.
- **D-03:** On clipboard failure: silent fail + German toast „Kopieren fehlgeschlagen“ (i18n DE/EN); no OS alert dialog.
- **D-04:** Clipboard **write/copy only** in 4.2 — no read/paste helpers. — **Reversibility:** reversible

### Update server & release channel
- **D-05:** Update server = **FaynoSync** self-hosted on Coolify — not CrabNebula. — **Reversibility:** costly — deploy + client endpoints.
- **D-06:** Updater signing now: generate updater keypair; **public** key in app config; **private** key only in CI/Coolify secrets — never git. **OS code-signing** (Apple Developer ID + Windows cert + notarization) **after** 4.2. — **Reversibility:** one-way — pubkey ships in clients; rotating needs coordinated release.
- **D-07:** Channel in 4.2: **`stable` only**; beta/nightly documented but not deployed.
- **D-08:** Prod update URL in build config; Staging separate endpoint env-gated; no user-configurable URL in UI; no Settings route.

### FaynoSync ops
- **D-09:** Public HTTPS subdomain for updates (e.g. `updates.…`); not buried only under API path.
- **D-10:** Releases: **CI upload + Founder manual** via FaynoSync UI allowed.
- **D-11:** Client update **check/download endpoints are public read**; integrity via updater signatures. Admin/upload authenticated. No client Bearer for checks; no VPN-only server.
- **D-12:** Separate Staging FaynoSync app/endpoint; prod builds never point at staging.

### Store migration & window state
- **D-13:** `tauri-plugin-store` holds Theme pref **and** future desktop prefs; Session stays Keychain (Phase 2). — **Reversibility:** costly — pref schema in store file.
- **D-14:** One-shot migration on app start: read `localStorage` `clared-theme` → store → cleanup localStorage key (fallback until success).
- **D-15:** Store wrapper: Tauri store in app; **localStorage fallback** when not in Tauri; Vitest mocks wrapper; plus **1–2 Tauri smoke/UAT** checks (theme survives restart / store file exists).
- **D-16:** Window position/size **only** via official `tauri-plugin-window-state` — do not duplicate in store.

### Updater & notification UX
- **D-17:** Check on startup + ~every 24h in background.
- **D-18:** On update available: in-app dialog with short changelog + „Jetzt installieren“ / „Später“.
- **D-19:** After download: user clicks „Neu starten“ (`tauri-plugin-process`); no forced restart mid-invoice; no 60s auto-restart.
- **D-20:** OS notifications in 4.2: **update ready** (+ debug test) only; sync/PDF alerts → Phase 5.
- **D-21:** Request notification permission **lazily** when first update is ready — not on cold start. Same policy macOS/Windows.
- **D-22:** If permission denied: keep in-app update dialog; optional one-shot hint to System Settings; never re-prompt every session.
- **D-23:** Silent check failures: log only (Sentry only on repeated failure); no toast. Manual „Prüfen“ failure: toast. Manual check with no update: toast „Aktuell“ (i18n). No exponential spam — next 24h slot / next start. Failed download: abort, cleanup temp, offer retry later — no corrupt apply.
- **D-24:** No auto-rollback in app; ops may publish older build on FaynoSync if needed. — **Reversibility:** reversible

### Update UI placement & artifacts
- **D-25:** Update check entry in **native app menu** („Auf Updates prüfen…“) + dialog on find; no Settings screen. Windows gets equivalent menu actions (parity).
- **D-26:** Version via native About when easy; else version in debug panel + update dialog chrome.
- **D-27:** macOS: Tauri updater archive (e.g. `.app.tar.gz`) for updates; DMG OK for first install distribution.
- **D-28:** Windows: **NSIS** as primary updater target (not dual NSIS+MSI in 4.2).
- **D-29:** FaynoSync = SSOT for auto-update; optional GitHub Release as human download/notes mirror.

### Changelog source
- **D-30:** Dialog changelog prefers FaynoSync release notes; if empty, show version number only. CI may mirror GH Release body into FaynoSync notes.

### Desktop feel
- **D-31:** `tauri-plugin-prevent-default`: block reload (F5/Ctrl-R), back/forward, disruptive zoom gestures; allow context menu in inputs. Map Cmd*↔Ctrl* on Windows.
- **D-32:** Text selection: labels/chrome not selectable; inputs, tabular money, copy targets selectable.
- **D-33:** Overscroll/rubber-band **off**.
- **D-34:** External link guard: `https:` → system browser (`opener`); `http:` only localhost/dev; `clared://` in-app; `file:`/unknown → block + log. Must not break Phase 2 Authentik/OIDC/deep-link. No driving external sites inside WebView (except documented auth exceptions).
- **D-35:** Community `dragout`: install + smoke in 4.2; real PDF drag-out UX → Phase 5.
- **D-36:** Startup flash: align with existing boot paint only — no splash redesign; same macOS/Windows behavior; native titlebar stays (Phase 4 D-19). Boot must not wait on Sentry/network.

### Observability — Sentry
- **D-37:** Sentry EU Free Cloud (`de.sentry.io`); GlitchTip **not** in 4.2 (defer until quota/compliance forces). — **Reversibility:** costly — DSN/project coupling.
- **D-38:** `sendDefaultPii: false`; env-gated (off or manual in local dev; on staging/prod).
- **D-39:** Error sample rate 1.0 on staging/prod. Performance tracing **off** or ≤0.1 staging only in 4.2.
- **D-40:** `beforeSend` scrub: tokens, Authorization, keychain values, email/name if present, invoice line / customer names in breadcrumbs/extras.
- **D-41:** Tag `release` = app version and `environment` = dev|staging|prod; CI sets release at build.

### Observability — Log
- **D-42:** Official `tauri-plugin-log` → app data log dir with rotation (plugin defaults).
- **D-43:** Levels: Dev=`debug`, Prod=`info` (errors always).
- **D-44:** No custom 30-day policy in 4.2 — plugin rotation defaults.
- **D-45:** „Open log folder“ only in debug panel — not in prod Help menu.

### Debug DX
- **D-46:** Cmd+D (Ctrl+D on Windows) debug panel **only** in debug/dev builds — dead in release.
- **D-47:** **Rich** panel: env, version, build time, auth logged-in yes/no + `/me` label (**no token**), theme + store keys (read/reset theme), window-state info, updater check-now + last check + masked endpoint, log level + open log path, Sentry test event, clipboard test copy, notification test ping, link-guard/prevent-default flags, plugin health checklist. No full Redux dump / network proxy / SQL/PDF tools.
- **D-48:** No Specta / TauRPC in 4.2; revisit when custom Rust IPC grows (prefer evaluate Specta before TauRPC). — **Reversibility:** reversible
- **D-49:** MCP bridge **unchanged** — keep current `#[cfg(debug_assertions)]` binding; do not add to release builds.
- **D-50:** WebView DevTools / F12 allowed in debug; Tauri standard `devtools` in debug builds; never in production.

### Security hardening
- **D-51:** In 4.2: tighten Tauri **capabilities** allowlists for all new plugins; replace `csp: null` with a sane CSP that does not break auth/dev — document any exceptions. — **Reversibility:** costly — wrong CSP breaks runtime.

### i18n
- **D-52:** Update dialogs, toasts, and related copy via existing i18next DE+EN (`fallbackLng: 'de'`).
- **D-53:** Native menu labels follow app i18n language; OS About may stay system-locale.
- **D-54:** User-facing strings DE/EN via i18n; **internal log and Sentry messages also German** (user preference).

### Claude's Discretion
- Exact FaynoSync Coolify service name/domain slug within D-09.
- Exact prevent-default rule list within D-31 (tauri-ui battery defaults OK).
- Exact CSP string within D-51 as long as auth + Vite dev keep working.
- Which 1–2 copy actions (D-02) if multiple candidates — prefer invoice number + tax rule id.
- Sentry repeated-failure threshold before event (D-23).

</decisions>
