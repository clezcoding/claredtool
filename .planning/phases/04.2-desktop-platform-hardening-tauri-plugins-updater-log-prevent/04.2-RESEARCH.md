### Locked Decisions
#### Clipboard
- **D-01:** Use official `tauri-plugin-clipboard-manager` only — not CrossCopy. — **Reversibility:** costly — plugin choice and call sites.
- **D-02:** Ship thin helper API plus 1–2 real copy actions where UI already exists (e.g. invoice number / tax rule id); broader copy UX → Phase 5.
- **D-03:** On clipboard failure: silent fail + German toast „Kopieren fehlgeschlagen“ (i18n DE/EN); no OS alert dialog.
- **D-04:** Clipboard **write/copy only** in 4.2 — no read/paste helpers. — **Reversibility:** reversible

#### Update server & release channel
- **D-05:** Update server = **FaynoSync** self-hosted on Coolify — not CrabNebula. — **Reversibility:** costly — deploy + client endpoints.
- **D-06:** Updater signing now: generate updater keypair; **public** key in app config; **private** key only in CI/Coolify secrets — never git. **OS code-signing** (Apple Developer ID + Windows cert + notarization) **after** 4.2. — **Reversibility:** one-way — pubkey ships in clients; rotating needs coordinated release.
- **D-07:** Channel in 4.2: **`stable` only**; beta/nightly documented but not deployed.
- **D-08:** Prod update URL in build config; Staging separate endpoint env-gated; no user-configurable URL in UI; no Settings route.

#### FaynoSync ops
- **D-09:** Public HTTPS subdomain for updates (e.g. `updates.…`); not buried only under API path.
- **D-10:** Releases: **CI upload + Founder manual** via FaynoSync UI allowed.
- **D-11:** Client update **check/download endpoints are public read**; integrity via updater signatures. Admin/upload authenticated. No client Bearer for checks; no VPN-only server.
- **D-12:** Separate Staging FaynoSync app/endpoint; prod builds never point at staging.

#### Store migration & window state
- **D-13:** `tauri-plugin-store` holds Theme pref **and** future desktop prefs; Session stays Keychain (Phase 2). — **Reversibility:** costly — pref schema in store file.
- **D-14:** One-shot migration on app start: read `localStorage` `clared-theme` → store → cleanup localStorage key (fallback until success).
- **D-15:** Store wrapper: Tauri store in app; **localStorage fallback** when not in Tauri; Vitest mocks wrapper; plus **1–2 Tauri smoke/UAT** checks (theme survives restart / store file exists).
- **D-16:** Window position/size **only** via official `tauri-plugin-window-state` — do not duplicate in store.

#### Updater & notification UX
- **D-17:** Check on startup + ~every 24h in background.
- **D-18:** On update available: in-app dialog with short changelog + „Jetzt installieren“ / „Später“.
- **D-19:** After download: user clicks „Neu starten“ (`tauri-plugin-process`); no forced restart mid-invoice; no 60s auto-restart.
- **D-20:** OS notifications in 4.2: **update ready** (+ debug test) only; sync/PDF alerts → Phase 5.
- **D-21:** Request notification permission **lazily** when first update is ready — not on cold start. Same policy macOS/Windows.
- **D-22:** If permission denied: keep in-app update dialog; optional one-shot hint to System Settings; never re-prompt every session.
- **D-23:** Silent check failures: log only (Sentry only on repeated failure); no toast. Manual „Prüfen“ failure: toast. Manual check with no update: toast „Aktuell“ (i18n). No exponential spam — next 24h slot / next start. Failed download: abort, cleanup temp, offer retry later — no corrupt apply.
- **D-24:** No auto-rollback in app; ops may publish older build on FaynoSync if needed. — **Reversibility:** reversible

## Summary

Phase 04.2 hardens the existing Tauri 2 desktop shell (`apps/desktop`) without migrating to a tauri-ui scaffold. Current Rust deps are opener, deep-link, single-instance, os, keyring, and debug-only mcp-bridge; `tauri.conf.json` still has `"csp": null`; CI builds DMG + NSIS/MSI artifacts without updater signing. Official Tauri plugins cover store, log, updater, process, window-state, notification, and clipboard-manager. Community crates cover prevent-default (Rust-only) and dragout (macOS-only — must be `cfg`-gated so Windows CI still builds). Sentry integration must use **`tauri-plugin-sentry` 0.6** + **`tauri-plugin-sentry-api`**, not the stale crates.io name `sentry-tauri` 0.3.1 (Tauri v1 tree). FaynoSync is the locked update server but is **not** deployed on Coolify yet (services today: Authentik, Vaultwarden, Docuseal only).

**Primary recommendation:** Plan five waves matching CONTEXT — (1) feel/plugins+capabilities/CSP, (2) log+Sentry, (3) FaynoSync Coolify + updater signing CI + process UX, (4) debug panel, (5) clipboard write — with Wave 0 tests/mocks and a human Coolify deploy checkpoint before ship verification.

### Pattern 1: Official plugin add + capability grant
**What:** Prefer `pnpm tauri add <name>` then tighten permissions (clipboard write-only).
**When to use:** Every official plugin in this phase.
**Example:**

```typescript
// Source: https://v2.tauri.app/plugin/clipboard/
import { writeText } from '@tauri-apps/plugin-clipboard-manager';
await writeText(value);
// Capabilities: clipboard-manager:allow-write-text ONLY (no allow-read-text) — D-04
```

### Pattern 2: Updater check → dialog → download → user relaunch
**What:** Never auto-relaunch mid-invoice; use process plugin on explicit confirm.
**Example:**

```typescript
// Source: https://v2.tauri.app/plugin/updater/
import { check } from '@tauri-apps/plugin-updater';
import { relaunch } from '@tauri-apps/plugin-process';

const update = await check();
if (update) {
  // show dialog with update.body (notes) — D-18/D-30
  await update.downloadAndInstall();
  // await relaunch() only after user clicks „Neu starten“ — D-19
}
```

### Pattern 3: Store + theme migration without boot flash regression
**What:** Async store for runtime; preserve first-paint path used by `index.html` boot IIFE.
**When to use:** D-13–D-15 + D-36.

### Pattern 4: Debug-only surfaces
**What:** Mirror mcp-bridge: Rust `#[cfg(debug_assertions)]`; frontend tree-shake or `import.meta.env.DEV` + never ship debug panel in release bundle.

### Anti-Patterns to Avoid
- **Installing `sentry-tauri` 0.3.1:** Wrong generation; use `tauri-plugin-sentry` 0.6.
- **Unconditional `tauri-plugin-dragout`:** README: other platforms fail to compile — breaks Windows CI.
- **`clipboard-manager:default` if it expands to read:** Prefer explicit `allow-write-text` only.
- **Putting theme in window-state or session keychain:** Violates D-13/D-16.
- **Cold-start notification permission / Sentry await before paint:** Violates D-21/D-36.
- **FaynoSync JS SDK + http plugin for 4.2:** Extra surface; native updater JSON is enough for D-30 notes.
- **Leaving `mcp-bridge:default` in release capabilities:** Plugin is debug-gated in Rust but permission still listed in `default.json` today — tighten.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Auto-update protocol + signatures | Custom download/apply | `tauri-plugin-updater` | Signature mandatory; platform archives differ |
| Process restart | `window.location` hacks | `tauri-plugin-process` `relaunch` | Clean native restart |
| Pref file format | Ad-hoc JSON in app data | `tauri-plugin-store` | Async load/save + ACL |
| Window geometry | Manual position IPC | `tauri-plugin-window-state` | OS multi-monitor edge cases |
| Shortcut blocking | Document keydown soup | `tauri-plugin-prevent-default` | WebView/OS differences |
| Crash/error pipeline | DIY POST | `tauri-plugin-sentry` + Sentry EU | Breadcrumb merge Rust+JS |
| Update server | Static GH latest.json only | FaynoSync (SSOT) + optional GH mirror | Channels, upload UI, signatures (D-05/D-29) |
| Clipboard | `navigator.clipboard` only | Plugin writeText | Tauri WebView permission quirks |

**Key insight:** Ship-readiness is mostly plugin wiring + capabilities/CSP + Coolify ops — not new product UI.

## Common Pitfalls

### Pitfall 1: Boot paint vs store migration
**What goes wrong:** After D-14 cleanup of `clared-theme`, `index.html` boot IIFE falls back to system and flashes wrong theme.
**Why:** Boot script is sync and only reads localStorage [VERIFIED: apps/desktop/index.html:37-42].
**How to avoid:** Dual-write theme to localStorage as boot mirror after store write, **or** set native window background from Rust before show; do not strip localStorage until mirror strategy exists.
**Warning signs:** First-launch-after-update theme flash in UAT.

### Pitfall 2: dragout breaks Windows CI
**What goes wrong:** `cargo build` on `windows-latest` fails.
**Why:** dragout is macOS-only and “purposely fails to compile” elsewhere [CITED: github.com/alexqqqqqq777/tauri-plugin-dragout].
**How to avoid:** `#[cfg(target_os = "macos")]` dependency + plugin init; document Windows no-op smoke.

### Pitfall 3: Wrong Sentry crate name
**What goes wrong:** Locking `sentry-tauri` 0.3.1 (v1).
**How to avoid:** `tauri-plugin-sentry` 0.6 + `sentry` 0.49; init before other plugins; env-gate DSN empty in dev.

### Pitfall 4: CSP / link-guard break OIDC
**What goes wrong:** Login WebView or deep-link callback fails after CSP or global navigation hooks.
**How to avoid:** Keep login allowlist + `clared://` handling in `lib.rs`; link-guard applies to main WebView only; CSP `connect-src` must include backend, Authentik, Sentry, update host, and Vite `http://localhost:5174` in dev [VERIFIED: tauri.conf.json:8 `devUrl`].

### Pitfall 5: FaynoSync platform/arch mismatch
**What goes wrong:** Always 204 / no update.
**Why:** Tauri templates use `{{target}}`=`darwin|windows|linux` and `{{arch}}`=`x86_64|aarch64`; FaynoSync examples use `platform=darwin&arch=amd64` [CITED: faynosync.com/docs/updaters/tauri].
**How to avoid:** Wave 0 integration test against staging FaynoSync; document exact endpoint string in `tauri.conf` / env.

### Pitfall 6: Updater private key in git or missing in CI
**What goes wrong:** Unsigned artifacts or leaked key.
**How to avoid:** `tauri signer generate`; pubkey content in config (not path); `TAURI_SIGNING_PRIVATE_KEY` in CI secrets only [CITED: v2.tauri.app/plugin/updater].

### Pitfall 7: MSI+NSIS dual updater confusion
**What goes wrong:** Clients fetch wrong Windows artifact.
**How to avoid:** D-28 — primary NSIS for updater uploads; keep MSI optional for human install only if still built.

### Pitfall 8: Notification permission on every launch
**What goes wrong:** Permission spam; user denial with no in-app path.
**How to avoid:** Lazy request on first update-ready (D-21); always keep in-app dialog (D-22).

| Pattern | STRIDE | Standard Mitigation |
