## Warnings

### WR-04: Rust Sentry scrub lacks free-text customer name redaction (D-40 parity gap)

**File:** `apps/desktop/src-tauri/src/lib.rs:373-401`  
**Issue:** The JS `beforeSend` scrub applies `CUSTOMER_NAME_IN_TEXT_RE` via `redactMessage` to top-level messages, exception values, and breadcrumb messages (`sentry.ts:10-11,31-34,99-112`). The Rust `sentry_scrub_event` path only redacts customer names when the field **key** matches (`sentry_key_is_name`); free-text patterns like `Kunde: Acme GmbH` in `event.message`, `exception.value`, or `breadcrumb.message` pass through unchanged. Native Rust / plugin-captured events that include invoice customer names in message text can leak PII to Sentry despite D-40.

**Fix:** Port the customer-name-in-text pattern to Rust and apply it wherever `sentry_redact_string` is called with `key: None` on message/exception/breadcrumb fields — e.g. a `sentry_redact_message(text: &str) -> String` helper that runs email + customer-name regex before returning. Add a unit test mirroring `sentry.test.ts` cases for `Kunde: Acme GmbH` on the Rust scrub path.

## Info

### IN-03: Updater endpoint URL duplicated in three places (drift risk)

**File:** `apps/desktop/src/components/debug-panel.tsx:42-43` (also `tauri.conf.json:57`, `patch-tauri-config.mjs:13-14`)  
**Issue:** IN-02 aligned the debug-panel constant with staging, but the FaynoSync checkVersion URL is still copied as string literals in `tauri.conf.json`, `patch-tauri-config.mjs`, and `debug-panel.tsx`. A future endpoint change requires touching all three; the debug panel can silently misreport the channel again.

**Fix:** Extract a single shared constant (e.g. `apps/desktop/src/lib/updater-endpoint.ts` imported by debug panel; build script reads from `tauri.conf.json` as SSOT) or read the configured endpoint at runtime via Tauri config / env when available.
