## Warnings

### WR-03: `EMAIL_RE` global flag causes intermittent email scrub misses

**File:** `apps/desktop/src/lib/sentry.ts:4,23-24`  
**Issue:** `EMAIL_RE` is defined with the `/g` flag and used via `.test()` inside `redactString`, which mutates `lastIndex` across calls. After a prior match on a longer string, a subsequent `.test()` on a shorter email-only value can return `false` (when `lastIndex >= value.length`) without matching, so the email is not redacted. Affects `extra`, `user`, headers, tags, messages, and breadcrumbs whenever multiple string fields are scrubbed in one event — a D-40 PII leak under realistic multi-field payloads.

**Fix:**
```typescript
const EMAIL_RE = /[^\s@]+@[^\s@]+\.[^\s@]+/; // drop /g — .test() must be stateless

function redactString(value: string, key?: string): string {
  if (key && TOKEN_KEY_RE.test(key)) return REDACTED;
  if (EMAIL_RE.test(value)) return value.replace(/[^\s@]+@[^\s@]+\.[^\s@]+/g, REDACTED);
  // ...
}
```
Add a test that scrubs two email-bearing fields in one `scrubSentryEvent` call and asserts both are redacted.
