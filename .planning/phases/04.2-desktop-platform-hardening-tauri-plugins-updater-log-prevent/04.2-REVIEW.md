## Summary

Desktop hardening deliverables are largely coherent: write-only clipboard capability, DEV-gated debug panel, link guard, updater state machine, log/Sentry wrappers, and prevent-default split across debug/release builds. Capability tests and plugin wiring match stated D-* requirements.

One **critical** updater state-machine defect can interrupt an in-progress download. Several **warnings** affect staging UAT, release CSP tightness, observability tagging, and PII scrub completeness. No hardcoded private signing keys in tracked files; clipboard read permission correctly omitted.

## Critical Issues

### CR-01: Manual update check can clobber active download

**File:** `apps/desktop/src/lib/updater.ts:136-159`  
**Issue:** `checkForUpdates` has no guard when `state === "downloading"`. A manual check (native menu in `theme-menu.ts:46`, debug panel in `debug-panel.tsx:186`) calls `setState("available", …)`, replaces `pluginUpdate`, and `update-dialog.tsx:152-154` clears progress whenever state leaves `"downloading"`. An in-flight `pluginUpdate.download()` can keep running while the UI reverts to "available", enabling overlapping download attempts and a corrupted update flow.

**Fix:**
```typescript
export async function checkForUpdates(
  manualOrOptions?: boolean | { manual?: boolean },
): Promise<UpdateInfo | null> {
  const manual = parseManual(manualOrOptions);
  if (!isTauriRuntime()) return null;
  if (state === "downloading") {
    if (manual) emitToast("update.downloading");
    return info;
  }
  // … existing check() logic
}
```

Disable manual check controls in UI while `state === "downloading"` as defense in depth.

## Warnings

### WR-01: Staging CI uploads artifacts the client cannot consume

**File:** `.github/workflows/desktop-build.yml:87-94`, `apps/desktop/src-tauri/tauri.conf.json:56-58`  
**Issue:** `publish-faynosync` on `main` pushes to the **staging** FaynoSync environment, but `plugins.updater.endpoints` is hardcoded to **production** `updates.puzzlessdev.online`. `04.2-UPDATER-OPS.md` documents a build-time staging gate that is not wired in workflow or `tauri.conf.json`. Staging UAT ("upload → check → install") cannot succeed with artifacts published only to staging.

**Fix:** Add a build-time endpoint substitution (e.g. `TAURI_UPDATER_ENDPOINT` env + `tauri.conf.json` template or separate staging config) for `workflow_dispatch` / non-tag `main` builds; keep prod URL for `v*` tags only (D-12).

### WR-02: Release CSP still allows dev origins and `unsafe-eval`

**File:** `apps/desktop/src-tauri/tauri.conf.json:25-32`  
**Issue:** CSP is static for all builds. Production bundles still allow `script-src 'unsafe-eval'`, `'unsafe-inline'`, and `http://localhost:5174`; `connect-src` includes localhost backend/auth hosts. A compromised in-app origin or XSS gains broader script/connect capability than production needs.

**Fix:** Split CSP by build profile (dev vs release) or strip localhost/`unsafe-eval` from release `tauri.conf.json` / build substitution once Vite bundle no longer needs eval.

### WR-03: Rust and JS Sentry environment tags can diverge

**File:** `apps/desktop/src-tauri/src/lib.rs:219-226`, `apps/desktop/src/lib/sentry.ts:76-81`  
**Issue:** Rust `sentry_environment()` uses `SENTRY_ENVIRONMENT` / `VITE_SENTRY_ENVIRONMENT` with fallback `"prod"`. JS `sentryEnvironment()` keys off `import.meta.env.MODE` (`staging` → `"staging"`). Staging builds without explicit env vars tag native vs frontend events differently, breaking D-41 environment consistency.

**Fix:** Share one source (build-injected `VITE_SENTRY_ENVIRONMENT` read by both sides, or Rust reads the same MODE-derived value).

### WR-04: `VITE_APP_VERSION` never injected at build

**File:** `apps/desktop/src/lib/sentry.ts:95`, `apps/desktop/src/components/debug-panel.tsx:168-169`, `apps/desktop/package.json:4`  
**Issue:** Release tag falls back to `"0.1.0"` while app version is `0.1.1`. Sentry release grouping and debug-panel version display drift from actual bundle version (D-41).

**Fix:** Inject at build time, e.g. Vite `define: { 'import.meta.env.VITE_APP_VERSION': JSON.stringify(version) }` sourced from `package.json` / `tauri.conf.json`.

### WR-05: `dismissUpdate` leaves stale `pluginUpdate` after errors

**File:** `apps/desktop/src/lib/updater.ts:207-210`, `apps/desktop/src/lib/updater.ts:199-204`  
**Issue:** `dismissUpdate` resets UI state but not `pluginUpdate`. After a failed download (`setState("error")` then dismiss), retry uses the same `Update` handle without re-running `check()`. Tauri updater may require a fresh metadata fetch after partial/failed install.

**Fix:**
```typescript
export function dismissUpdate(): void {
  emitProgress(null);
  pluginUpdate = null;
  setState("idle", null);
}
```
In `downloadUpdate` catch, consider `pluginUpdate = null` before `setState("error", …)`.

### WR-06: `useDownloadEta` mutates refs during render

**File:** `apps/desktop/src/components/update-dialog.tsx:33-58`  
**Issue:** `startedAt.current` and `lastBytes.current` are written during render when `progress` changes. Violates Rules of Hooks; StrictMode/double-render can reset ETA baseline and show wrong estimates.

**Fix:** Move ref updates into `useEffect` keyed on `progress?.downloadedBytes` / `progress?.phase`, or derive ETA in the download event handler inside `updater.ts`.

### WR-07: Windows FaynoSync upload failures are swallowed

**File:** `.github/workflows/desktop-build.yml:162-163`  
**Issue:** `continue-on-error: true` on the Windows upload step lets the publish job succeed when only macOS artifacts land. Silent Windows release gaps until manual inspection.

**Fix:** Remove `continue-on-error` once NSIS signing is stable, or add a required post-upload `checkVersion` for `platform=windows` (mirror macOS verify step).

### WR-08: Sentry scrub misses breadcrumb message text

**File:** `apps/desktop/src/lib/sentry.ts:65-68`  
**Issue:** `scrubSentryEvent` scrubs breadcrumb `data` but not `message`. Emails or customer names in breadcrumb messages (D-40) can still reach Sentry.

**Fix:**
```typescript
breadcrumbs: event.breadcrumbs?.map((crumb) => ({
  ...crumb,
  message: crumb.message
    ? redactString(crumb.message)
    : crumb.message,
  data: scrubRecord(crumb.data),
})),
```

### IN-01: Publish verify covers macOS only

**File:** `.github/workflows/desktop-build.yml:195-199`  
**Issue:** Post-upload verification runs `checkVersion` for `darwin/aarch64` only. Windows artifact upload regressions are not caught in CI.

**Fix:** Add analogous `checkVersion` curl for `platform=windows&arch=x86_64` when Windows upload is required.
