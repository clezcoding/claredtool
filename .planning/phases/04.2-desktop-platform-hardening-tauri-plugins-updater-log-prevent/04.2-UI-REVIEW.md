## Top 3 Priority Fixes

1. **Suppress redundant changelog panel when notes equal version** — When FaynoSync release notes are empty, `formatNotes` falls back to version string (`updater.ts:69-72`) but `UpdateDialog` still renders a bordered notes box duplicating the title's `{{version}}` — users see the same version twice with no changelog context — In `update-dialog.tsx`, skip the notes `<div>` when `!notes.trim() || notes.trim() === version` (D-30 version-only intent).

2. **Replace hardcoded `text-green-600` in debug panel** — Plugin health OK state uses Tailwind palette green instead of semantic tokens (`debug-panel.tsx:383`) — breaks dark-mode/token consistency and 60/30/10 accent discipline — Use `text-primary` or a semantic success/muted pair from the design system.

3. **Localize download ETA units** — `formatEta` emits hardcoded `"s"` / `"min"` strings (`update-dialog.tsx:25-30`) — English/German users get mixed-language ETA when app locale differs — Route through i18n keys (e.g. `update.etaSeconds`, `update.etaMinutes`) with `t()` in `formatEta` or pass locale-aware formatter from `useTranslation`.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

**WARNING — Redundant version copy in update dialog**
- `updater.ts:69-72` sets `notes` to `version` when FaynoSync body is empty (D-30).
- `update-dialog.tsx:218-223` title already includes `{{version}}`; `249-252` still renders notes panel with the same string.
- Impact: Dialog reads like a bug (empty changelog box showing only the version again).

**WARNING — ETA strings not i18n**
- `update-dialog.tsx:25-30` `formatEta` uses literal `"s"` and `"min"` regardless of `useTranslation` locale.
- EN `update.eta` template wraps these (`en.json:113`) but units stay English/German-mixed in DE mode uses "min" (acceptable) while other locales would break.

**PASS — User-facing update and clipboard copy**
- `de.json:95-120` / `en.json:95-120` — full `update.*` contract: install/later/relaunch, download phases, permission hint, menu label, toasts.
- `clipboard.failed` DE/EN present; copy buttons use `invoice.copyNumber` / `tax.copyRuleId` aria-labels (`rechnung.tsx:988`, `tax.tsx:96`).

**INFO — Debug panel German-only (acceptable)**
- `debug-panel.tsx:253-256` and section labels are hardcoded German.
- D-46/D-47 scope is DEV-only diagnostics; not a ship blocker. Optional: extract to `debug.*` i18n keys if EN devs are common.

**INFO — Native menu partial i18n**
- `theme-menu.ts:44` uses `i18n.t("update.menuCheck")` for update action (good).
- Darstellung submenu labels (`Hell`/`Dunkel`/`System`) remain hardcoded German — pre-existing Phase 4 pattern, not introduced in 04.2.

### Pillar 2: Visuals (3/4)

**WARNING — Screenshot coverage gap**
- Playwright capture at `:5174` returned boot `Splash` only (unauthenticated).
- Update dialog, debug panel, and copy buttons were not visually verified in screenshots — audit relies on code review for those surfaces.

**PASS — Update dialog focal hierarchy**
- `update-dialog.tsx:244-247` — title → description → content → footer CTA order clear.
- Progress panel (`104-149`) separates phase label, percent, ETA on one row; bar uses `role="progressbar"` with `aria-valuenow` / `aria-label`.

**PASS — Copy affordances**
- Icon-only copy buttons include `aria-label` and `size-7` hit targets (`rechnung.tsx:986-993`, `tax.tsx:94-104`).
- Invoice field uses `copyable` class for text selection per D-32 (`rechnung.tsx:983`).

**WARNING — Notes panel when content is version-only**
- Bordered `max-h-48` scroll region (`update-dialog.tsx:250-252`) adds visual weight without informational gain when notes === version.

### Pillar 3: Color (3/4)

**WARNING — Off-token success color in debug panel**
- `debug-panel.tsx:383` — `{ok ? "text-green-600" : "text-muted-foreground"}` uses raw Tailwind green, not `--primary` / semantic success token.
- Only new hardcoded color in phase UI components (grep found no `#hex` or `rgb(` in `apps/desktop/src/**/*.tsx`).

**PASS — Update dialog accent discipline**
- Single accent use: progress fill `bg-primary` (`update-dialog.tsx:142`).
- Surfaces use `bg-surface-container-low`, `border-border`, `text-destructive` for error — aligned with token system.

### Pillar 4: Typography (4/4)

**PASS — Phase UI font scale**
- `update-dialog.tsx`: `text-sm`, `text-xs`, `font-medium`.
- `debug-panel.tsx`: `text-sm`, `text-xs`, `font-semibold`, `font-mono` for values.
- 2 size steps, 2 weight roles (+ mono for data) — under abstract >4 sizes / >2 weights threshold.

**PASS — No new arbitrary font sizes in phase components**
- Icon sizes `text-[16px]` on copy buttons follow existing MaterialIcon pattern from Phase 4.1.

### Pillar 5: Spacing (4/4)

**PASS — Consistent spacing scale in new UI**
- `update-dialog.tsx`: `space-y-2`, `gap-3`, `px-3 py-2`, `sm:max-w-md`.
- `debug-panel.tsx`: `grid gap-3`, section `p-3`, `space-y-1`/`space-y-2`.
- `app-shell.tsx` feedback line `px-8 pt-3` matches existing main padding rhythm.

**PASS — No arbitrary spacing in phase-only components**
- Grep for `[.*px]` / `[.*rem]` in `update-dialog.tsx` and `debug-panel.tsx`: none.

### Pillar 6: Experience Design (4/4)

**PASS — Update dialog state coverage**
- States: `available`, `downloading`, `ready`, `error` (`update-dialog.tsx:203-207`).
- Download: close button hidden, escape/outside prevented (`236-242`), install button disabled while `isInstalling` (`278-280`).
- Ready: user-initiated relaunch only (`304-306`) — D-19 compliant.
- Error: `text-destructive` message + retry via install CTA (`263-265`, `268-284`).

**PASS — Notification permission UX**
- Lazy request on `ready` (`181-189`); one-shot permission hint via `localStorage` (`94-98`, `259-261`) — D-21/D-22.

**PASS — Clipboard failure path**
- `copyText` returns boolean; routes call `setFeedback(t("clipboard.failed"))` on false (`rechnung.tsx:471-472`, `tax.tsx:72-74`) — D-03 silent success + toast on fail.

**PASS — Manual update feedback**
- `app-shell.tsx:90-94` subscribes to `subscribeUpdateToasts` for `update.current` / `update.manualFail` etc.
- `role="status"` on feedback line (`220`) for screen readers.

**PASS — Debug panel DEV gate**
- `DEBUG_PANEL_ENABLED = import.meta.env.DEV` (`debug-panel.tsx:41`); dynamic import in `app-shell.tsx:60-64`; Cmd/Ctrl+D skips editable targets (`39-44`, `67-84`).

**PASS — Global desktop feel (D-32/D-33)**
- `globals.css:194` `overscroll-behavior: none`; `208-216` chrome `user-select: none` with `.copyable` / `.tabular-nums` exceptions.

**INFO — Toast persistence**
- AppShell `feedback` state has no auto-dismiss timer — manual update toasts remain until next message. Acceptable for low-frequency update checks; optional polish: timed dismiss for `update.current`.
