## Signing keys (D-06)

| Item | Location | Notes |
|------|----------|-------|
| Public key (minisign) | `apps/desktop/src-tauri/tauri.conf.json` → `plugins.updater.pubkey` | Ships in every client build; one-way door |
| Private key | **Never in git** | `TAURI_SIGNING_PRIVATE_KEY` GitHub Actions secret |
| Private key (optional path) | CI only | `TAURI_SIGNING_PRIVATE_KEY_PATH` if file-based signing preferred |
| Password | N/A for this keypair | Generated passwordless via `tauri signer generate --ci`; set `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` only if key is re-generated with a password |

### Secret placement checklist

1. Copy private key material from the secure generation output (local operator session only).
2. GitHub repo → Settings → Secrets → Actions → `TAURI_SIGNING_PRIVATE_KEY` (full key string).
3. Optional Coolify env on CI runner or release automation if not using GitHub Actions alone.
4. Confirm `git grep` / secret scan finds no private key in tracked files.

**OS code-signing** (Apple Developer ID, Windows Authenticode, notarization) remains **deferred** after Phase 04.2 (D-06).

### Garage public asset CDN (2026-08-28)

Coolify routes `updates-assets*.puzzlessdev.online` to Garage **web** port `3902`. Garage expects `Host: cb-faynosync-s3-public.web.garage.localhost`; without it, `checkVersion` URLs 404 even when upload succeeds.

**Fix (in compose `s3` service):** Garage `s3_web` binds `3904`; Caddy on `3902` proxies with `Host` header:

```sh
caddy reverse-proxy --from :3902 --to 127.0.0.1:3904 --header-up 'Host: cb-faynosync-s3-public.web.garage.localhost'
```

Also set `S3_ENDPOINT_PRIVATE` to port `3904` (not `3902`). Verify artifact:

```bash
curl -sS -o /dev/null -w "%{http_code} size=%{size_download}\n" \
  "$(curl -sS 'https://updates.puzzlessdev.online/checkVersion?app_name=clared&version=0.1.1&platform=darwin&arch=aarch64&channel=stable&updater=tauri&owner=admin' | jq -r .url)"
# expect: 200 size≈32612067
```

Then in FaynoSync admin UI at the **Admin dashboard** URL above:

1. **Sign up** with the `API_KEY` value from Coolify env (not `FAYNOSYNC_ADMIN_CREDENTIALS` — that is HTTP basic-auth for the API only).
2. Create application **`clared`**
3. Add channel **`stable`** (only channel used in 4.2 per D-07)
4. Repeat on staging service for staging smoke tests (D-12)

Until app+channel exist, `checkVersion` returns HTTP 400 (`Channel does not exist`). Without `owner=admin`, HTTP 400 (`app_name not found in apps_meta`). With app+channel seeded but **no published release yet**, HTTP 400 (`no matching documents found`) — expected until first signed artifact upload. Health `/health` should still return 200.

## FaynoSync endpoints

| Environment | checkVersion template (stable + tauri) |
|-------------|----------------------------------------|
| Production | `https://updates.puzzlessdev.online/checkVersion?app_name=clared&version={{current_version}}&platform={{target}}&arch={{arch}}&channel=stable&updater=tauri&owner=admin` |
| Staging | `https://updates-staging.puzzlessdev.online/checkVersion?app_name=clared&version={{current_version}}&platform={{target}}&arch={{arch}}&channel=stable&updater=tauri&owner=admin` |

`owner=admin` matches the FaynoSync dashboard signup user (FaynoSync scopes `apps_meta` by owner).

**Client wiring (D-08, D-12):** Prod URL is baked into `tauri.conf.json` `plugins.updater.endpoints`. Staging URL is selected only via build-time env gate for staging CI builds — prod release builds must never point at staging.
