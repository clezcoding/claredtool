# Phase 04.7 — UI Design Contract

> Visual and interaction contract for **desktop stammdaten dialog extensions** only (Entity / Customer / Invoice). Generated by gsd-ui-researcher. Backend XML/PDF/A-3 bytes are out of this contract’s visual scope; UI must collect facts those serializers need.
>

## Spacing Scale

Declared values (multiples of 4) — inherit Crafted Minimal / 04.1:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Field-error gap under input; icon gaps |
| sm | 8px | Compact stack inside dialog field groups (`gap-2`) |
| md | 16px | Default field stack / dialog body padding rhythm |
| lg | 24px | Section breaks inside dialog (Allgemein → Adresse → Bank) |
| xl | 32px | Layout gaps (unchanged shell) |
| 2xl | 48px | Major section breaks (unchanged) |
| 3xl | 64px | Page-level (unchanged; unused in dialogs) |

Radius: `--radius-sm 4px`, `--radius-md 8px` (default), `--radius-lg 12px`. Dialog controls `rounded-md` / existing `rounded-lg` on footer buttons — do not invent new radius.

**Exceptions:**
- Interactive dialog controls keep **44px** (`min-h-11`) hit target (Phase 3/04.1 carry).
- Structured address uses a **2-column grid** on `md+` for postal+city (`gap-2` / `gap-4`); single column on narrow dialog width.
- No new 6px/12px scale tokens.

## Typography

Exactly four sizes, two weights (form chrome on dialogs — not Stitch 1:1 pixel soup):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 | 1.4 |
| Body | 14px | 400 | 1.5 |
| Heading (dialog section / screen) | 20px | 600 | 1.3 |
| Display (existing Entity DialogTitle only) | 32px | 600 | 1.15 |

Weights limited to **400** and **600**. Do not introduce `font-medium` (500) on new 04.7 fields. Existing DialogTitle `text-[32px]` on Entity/Kunde create stays; new section headers inside dialogs use Heading 20px/600.

Placeholders and helper hints: Label size, `text-muted-foreground`. Field values: Body 14px. IBAN/BIC: Body + `tabular-nums` (optional `font-mono` only if existing bank tab already uses it — do not invent a third weight).

## Color

Crafted Minimal 60/30/10 (light) — locked from Phase 04 / 04.1:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F7F5` Pale Oatmeal (`--background`) | App chrome behind dialogs |
| Secondary (30%) | `#FFFFFF` Pure White (`--card` / dialog surface) | Dialog panel, inputs |
| Accent (10%) | `#A8BFA3` Sage (`--primary` / `--primary-container` for filled CTAs) | See reserved-for |
| Destructive | `#C9A227` Amber (`--destructive`) | Field validation + fail-closed error text only |

Foreground: `#111110`. Muted: `#8A8A8A`. Border: `#E8E8E4` light / `#2A2A28` dark.

**Accent (Sage) reserved for:**
- Dialog primary submit (**Anlegen** / existing create submit)
- Focus ring (`--ring`) on new inputs/selects
- Selected `supplyType` segment or Select value affordance when using primary-container pattern from 04.1

Never paint Sage on every label, optional-field chrome, or bank hints.

**Destructive reserved for:**
- Inline field errors (incomplete structured address, invalid optional format when filled)
- Dialog-level fail-closed banners (mixed supplyType; server fail-closed with scrubbed message)
- Not used on optional IBAN/Leitweg empty state

Dark theme: single tree + `dark:` (04.1 D-07). No new theme tokens for e-invoice.

## Visual Hierarchy

**Primary screens this phase = Entity/Kunde create Dialog** (Rechnung `supplyType`/`unit` are secondary chrome on an existing canvas).

1. **First focal point:** structured **Adresse** block (Straße → Adresszusatz → PLZ+Ort grid → Land). Eye lands here after DialogTitle; this is the new mandatory e-invoice stammdaten work.
2. **Second:** optional Bank / Leitweg / Buyer-Ref sections below (muted weight; no Sage).
3. **Close of the scan:** DialogFooter — primary Sage **Anlegen**, secondary dismiss **Dialog schließen** / **Close dialog**.

Do not introduce a competing hero, badge strip, or side panel inside the dialog. List behind the modal stays visually dimmed (existing Dialog overlay).

**Rechnung (secondary):** `supplyType` sits in the invoice meta cluster (with dates/currency); `unit` sits on each `LineItemCard` beside menge — neither steals the Entity/Kunde dialog focal contract.

### Rechnung canvas — D-30 / D-31

| Control | Placement | Behavior |
|---------|-----------|----------|
| `supplyType` | Invoice header/meta cluster (near currency/dates) | `Select` or two-option control: **Ware** (`goods`) · **Leistung** (`service`). Default remains Prisma `service`. One value per invoice. |

- **Generate path:** not exposed in UI this phase; Nest fail-closed requires seller email+phone (BG-6). If any internal/API error surfaces in desktop (e.g. prep hook), show fail-closed copy with **no PII** (D-11/D-32).

## Interaction & a11y (phase-specific)

- Every new field: visible `<Label htmlFor>` + matching control `id`.
- `supplyType` and `unit`: keyboard-operable `Select` (Arrow/Enter/Escape); `aria-invalid` when error.
- Dialog dismiss unchanged: Escape/Close; Back does not dismiss (04.1 D-36).
- Optional fields: never marked required in DOM (`aria-required` only on street/postal/city/country and EU VAT when visible).
- Errors announced via existing inline text under field (and `aria-describedby` when wiring is trivial); color not sole signal (Amber text + message).
