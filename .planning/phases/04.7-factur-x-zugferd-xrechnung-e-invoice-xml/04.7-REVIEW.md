# Phase 04.7: Code Review Report

**Reviewed:** 2026-09-05T23:57:00Z
**Depth:** standard
**Files Reviewed:** 37
**Status:** issues_found

## Summary

Phase 04.7 delivers a solid dual-serializer core (`@clared/e-invoice`), hybrid PDF/A-3b embed, Nest fail-closed generate gates, stammdaten UI, and Mustang/KoSIT CI. Adversarial review still finds one production-migration blocker and several contract gaps: CII drops BT-10, buyer email required at generate but absent from Customer stammdaten, addressLine2 never reaches XML, and CI Schematron does not watch Nest PDF mapping changes.

## Critical Issues

### CR-01: Stammdaten migration unsafe on non-empty databases

**File:** `apps/backend/prisma/migrations/20260906000000_e_invoice_stammdaten/migration.sql:1-21`
**Issue:** Migration `DROP COLUMN "address"` then adds `street` / `postal_code` / `city` as `TEXT NOT NULL` with no `DEFAULT` and no backfill. On any `entities`/`customers` table with rows, `prisma migrate deploy` fails in PostgreSQL (cannot add NOT NULL without default). Existing free-text addresses are discarded rather than mapped into structured columns. SUMMARY acknowledges local `--force-reset`; Coolify deploy of this migration on live data is unsafe.
**Fix:**
```sql
-- Expand in a multi-step migration, e.g.:
ALTER TABLE "entities" ADD COLUMN "street" TEXT;
ALTER TABLE "entities" ADD COLUMN "postal_code" TEXT;
ALTER TABLE "entities" ADD COLUMN "city" TEXT;
UPDATE "entities" SET
  street = COALESCE(NULLIF(trim(split_part(address, E'\n', 1)), ''), 'UNKNOWN'),
  postal_code = '00000',
  city = 'UNKNOWN'
WHERE street IS NULL;
ALTER TABLE "entities" ALTER COLUMN "street" SET NOT NULL;
ALTER TABLE "entities" ALTER COLUMN "postal_code" SET NOT NULL;
ALTER TABLE "entities" ALTER COLUMN "city" SET NOT NULL;
ALTER TABLE "entities" DROP COLUMN "address";
-- Same pattern for customers.
```
Or document and enforce empty-DB-only deploy with an explicit ops gate before Coolify `migrate deploy`.

## Warnings

### WR-01: CII serializer drops `buyerReference` (BT-10 / Leitweg)

**File:** `packages/e-invoice/src/serialize-cii.ts:74-98`
**Issue:** `En16931Facts.buyerReference` is set by Nest (`invoice-pdf.service.ts` leitweg preference) and emitted in UBL (`serialize-ubl.ts:108-111`), but `serializeCiiComfort` never writes a buyer reference / order reference into the CII graph. Hybrid `factur-x.xml` therefore loses Leitweg while the parallel XRechnung artifact keeps it. Nest B2G tests only assert UBL, so this gap is silent.
**Fix:** Map `facts.buyerReference` into the node-zugferd EN16931 field for buyer reference (e.g. trade agreement buyer order / referenced document per library schema) and add a unit assertion that CII XML contains the Leitweg when present on facts.

### WR-02: Generate requires buyer email; Customer stammdaten cannot store it

**File:** `apps/backend/prisma/schema.prisma:37-55`
**Issue:** `InvoicePdfService.validateInput` fail-closes without `customer.email` (`invoice-pdf.service.ts:156-158`) for XRechnung EndpointID. `Customer` model, `CreateCustomerDto`, and desktop `kunden.tsx` have no email field. Any Phase 5 wire from DB → `InvoicePdfService` cannot satisfy the gate without inventing data or extending schema.
**Fix:** Add optional `email` on `Customer` (+ migration, DTO `@IsEmail`, Kunden dialog), or relax/document an alternate BT-49 source before generate is wired from persistence.

### WR-03: `addressLine2` never reaches e-invoice XML

**File:** `apps/backend/src/pdf/invoice-pdf.service.ts:235-258`
**Issue:** `addressLine2` is included in visual `formatDisplayAddress` only. `toFacts` maps only `street` → `line1`. Structured second address line collected in Entity/Customer UI is omitted from CII/UBL postal address.
**Fix:** Extend `PartyAddress` with optional `line2` and emit UBL `cbc:AdditionalStreetName` / CII equivalent when present.

### WR-04: Validator pin download has no integrity check

**File:** `tooling/e-invoice/download-pins.sh:23-31`
**Issue:** Jars/zips are fetched with `curl -fsSL` and cached by filename only. No SHA-256 (or similar) from `versions.lock.json` is verified before Mustang/KoSIT run in CI. Compromised release asset or cache poison would still “validate.”
**Fix:** Store expected digests in `versions.lock.json` and `sha256sum -c` (or equivalent) after each download before writing `paths.env`.

### WR-05: Schematron CI path filter misses Nest PDF mapping

**File:** `.github/workflows/ci.yml:78-83`
**Issue:** `e-invoice-validate` runs when `e-invoice`, `pdf-templates`, or `shared` change. Changes under `apps/backend/src/pdf/**` alone run unit tests but skip Mustang/KoSIT. Nest `toFacts` / serialize call-site regressions can land without Schematron.
**Fix:** Add `apps/backend/src/pdf/**` (and optionally fixtures under backend) to the `e-invoice` path filter, or always run `e-invoice-validate` when `backend` is true.

### WR-06: Unit price uses `netAmount / quantity` without zero guard

**File:** `packages/e-invoice/src/serialize-cii.ts:54`
**Issue:** Same pattern in `serialize-ubl.ts:91`. Nest PDF validates `menge > 0`, but the package public serializers do not. `quantity === 0` yields `Infinity`/`NaN` money strings and opaque `SERIALIZE_FAILED` / amount mismatch.
**Fix:**
```typescript
if (!(line.quantity > 0) || !Number.isFinite(line.quantity)) {
  throw new EInvoiceError("SERIALIZE_FAILED");
}
const unitPrice = moneyStr(line.netAmount / line.quantity);
```

### WR-07: Invoice line DTOs allow non-positive quantities

**File:** `apps/backend/src/invoices/dto/create-invoice.dto.ts:12-24`
**Issue:** `menge` / `einzelpreis` are only `@IsNumber()` — zero/negative values persist via `InvoicesService`. Generate later fail-closes, but invalid drafts are stored.
**Fix:** Add `@IsPositive()` (or `@Min(0.01)`) on `menge` and `@Min(0)` on `einzelpreis`.

## Info

### IN-01: `mapVatCategory` only accepts 19% standard rate for `S`

**File:** `packages/e-invoice/src/map-tax.ts:9-16`
**Issue:** Reduced 7% (and other shown rates) throw `TAX_MAPPING`. Matches Wave 1 scope; will block real DE reduced-rate invoices until extended.
**Fix:** Document as known ceiling; extend allowlist when PDF-01 expands beyond 19%/AE.

### IN-02: Hardcoded `VATEX-EU-AE` for every AE breakdown in CII

**File:** `packages/e-invoice/src/serialize-cii.ts:112-116`
**Issue:** Domestic DE §13b fixtures also emit EU reverse-charge exemption code. May be wrong for purely domestic RC; UBL emits reason text only.
**Fix:** Confirm against KoSIT/EN16931 code list; gate code on cross-border vs domestic or omit code when only legal text applies.

### IN-03: Line `netto` computed without `roundEur` in Nest create/update

**File:** `apps/backend/src/invoices/invoices.service.ts:64`
**Issue:** `netto: row.menge * row.einzelpreis` can retain binary float noise before Decimal persist; PDF path re-rounds independently.
**Fix:** Use shared `roundEur` (or Decimal multiply) at write time for parity with e-invoice totals.
