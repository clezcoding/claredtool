## Critical Issues

### CR-01: D-23 span deny-list incomplete — `http.url` and `db.statement` still exported

**Severity:** BLOCKER
**File:** `apps/backend/src/telemetry/otel.ts:18-22`
**Also:** `apps/backend/src/telemetry/otel.ts:59-70`, `apps/backend/src/telemetry/otel.spec.ts:43-52`

**Issue:** Iteration-1 CR-02 wired `AllowlistSpanProcessor`, but `isAllowedSpanAttribute` only rejects keys whose **names** match token/name/iban regexes. Auto-instrumentation attaches attributes whose **values** carry PII while the key name is innocuous:

- `http.url` / `url.full` / `http.target` — auth callback URLs include `?ticket=…` (see `lib.rs` `clared://` ticket flow). `isAllowedSpanAttribute("http.url")` returns `true`.
- `db.statement` — `@opentelemetry/instrumentation-pg` is configured with `requireParentSpan: true` only; statement text is not disabled. Prisma queries can embed customer names/IBAN in SQL. `db.statement` does not match any deny regex.

Redis/ioredis statement capture is correctly blanked; HTTP and PG gaps remain. `otel.spec.ts` tests key-name predicates only — it never asserts `http.url` or `db.statement` are denied, so the regression is invisible.

**Fix:** Extend the deny-list and disable PG statement capture:

```typescript
const URL_KEY_RE = /^(http\.(url|target|route|path)|url\.full)$/i;
const DB_STATEMENT_KEY_RE = /^db\.statement$/i;

export function isAllowedSpanAttribute(key: string): boolean {
  if (URL_KEY_RE.test(key)) return false;
  if (DB_STATEMENT_KEY_RE.test(key)) return false;
  if (TOKEN_KEY_RE.test(key)) return false;
  if (NAME_KEY_RE.test(key)) return false;
  if (IBAN_LINE_KEY_RE.test(key)) return false;
  return true;
}

// in autoInstrumentations():
"@opentelemetry/instrumentation-pg": {
  requireParentSpan: true,
  enhancedDatabaseReporting: false,
},
```

Add spec cases: `expect(isAllowedSpanAttribute("http.url")).toBe(false)` and `expect(isAllowedSpanAttribute("db.statement")).toBe(false)`.

## Warnings

### WR-01: `TAURI_ENV_DEBUG` never set — `debug.json` SQL capabilities unreachable in dev

**Severity:** WARNING
**File:** `apps/desktop/src-tauri/build.rs:25-29`
**Also:** `apps/desktop/src-tauri/capabilities/debug.json`, `apps/desktop/scripts/tauri.mjs`, `apps/desktop/src/components/debug-panel.tsx:288-304`

**Issue:** WR-05 correctly removed `sql:allow-*` from release `default.json` and moved them to `debug.json`, gated on `std::env::var("TAURI_ENV_DEBUG")`. No script in the repo exports that variable; `@tauri-apps/cli` does not set it during `cargo`/`build.rs` either (only documented for `beforeDevCommand` hook scripts). Release builds correctly exclude SQL permissions, but `tauri dev` also builds with `{default,login}.json` only — debug-panel offline SQL smoke (`Database.load` / `db.select`) fails with ACL permission denied even though the panel mounts in DEV.

**Fix:** Gate on Rust debug profile instead of an unset env var, or export the var from the dev wrapper:

```rust
// build.rs — prefer cfg over unset env
let tauri_attrs = if cfg!(debug_assertions) {
    tauri_build::Attributes::new().capabilities_path_pattern("./capabilities/*.json")
} else {
    tauri_build::Attributes::new()
        .capabilities_path_pattern("./capabilities/{default,login}.json")
};
```

Alternatively, in `scripts/tauri.mjs`, set `TAURI_ENV_DEBUG=1` when `args[0] === "dev"`.

### WR-02: Worker never closes application context on shutdown

**Severity:** WARNING
**File:** `apps/backend/src/worker.ts:9-15`
**Also:** `apps/backend/src/pdf/pdf.processor.ts:7-17`, `apps/backend/src/pdf/gotenberg.client.ts:47`

**Issue:** `NestFactory.createApplicationContext(WorkerModule)` result is discarded. No `SIGTERM`/`SIGINT` handler calls `app.close()`. On container stop or deploy, BullMQ workers may not drain; in-flight Gotenberg converts (up to 30s `AbortSignal.timeout`) can be cut mid-flight; lock held until `lockDuration` (45s) expires, causing duplicate PDF renders on retry.

**Fix:**

```typescript
async function bootstrap() {
  initOtel({ serviceName: "clared-worker" });
  const log = pino(pinoBaseOptions("clared-worker"));
  log.info("Worker gestartet");
  const app = await NestFactory.createApplicationContext(WorkerModule);
  const shutdown = async () => {
    await app.close();
    process.exit(0);
  };
  process.on("SIGTERM", () => void shutdown());
  process.on("SIGINT", () => void shutdown());
}
bootstrap().catch((err) => {
  console.error(err);
  process.exit(1);
});
```
