## Narrative Findings (AI reviewer)

## Summary

Phase 04.3 wiring is mostly the planned skeleton: Gotenberg client + BullMQ worker, Pino/OTel boot, SQLCipher empty DB, debug-panel smokes. Two defects block ship: documented local stack cannot bind Nest and Gotenberg on the same host port, and the D-23 span-attribute allowlist is never installed on the SDK (tests only exercise the predicate). Remaining items are fail-open Gotenberg URL, missing convert/job timeouts, incomplete Pino paths, over-broad SQL capabilities, and a production deploy trigger that is not main-only.

## Critical Issues

### CR-01: Host port 3000 collision — Nest and Gotenberg cannot run together

**Severity:** BLOCKER
**File:** `compose.clared.yml:27-28`
**Also:** `apps/backend/.env.example:19`, `apps/backend/.env.example:25`, `apps/backend/src/main.ts:34`, `apps/backend/src/pdf/pdf.contract.ts:22`

**Issue:** Documented local workflow is Nest on the host (`pnpm --filter ./apps/backend start`, `PORT` default 3000, `BACKEND_URL=http://localhost:3000`) plus Gotenberg from Compose bound to `127.0.0.1:3000:3000` with `GOTENBERG_URL=http://127.0.0.1:3000`. Second listener on 3000 fails (`EADDRINUSE`). Worker in Compose talks to `http://gotenberg:3000` (docker DNS) and does not need the host publish; the host mapping exists only for laptop Nest/curl and fights the API.

**Fix:** Publish Gotenberg on a free host port; keep container port 3000 for the docker network.

```yaml
# compose.clared.yml
gotenberg:
  ports:
    - "127.0.0.1:3001:3000"
```

```dotenv
# apps/backend/.env.example
BACKEND_URL=http://localhost:3000
GOTENBERG_URL=http://127.0.0.1:3001
```

Leave worker `GOTENBERG_URL: http://gotenberg:3000`. Update `DEFAULT_GOTENBERG_URL` + contract spec to the host-local sample (or drop the default and require env).

### CR-02: D-23 span allowlist never applied; auto-instrumentation can export PII

**Severity:** BLOCKER
**File:** `apps/backend/src/telemetry/otel.ts:41-68`
**Also:** `apps/backend/src/telemetry/otel.ts:20-25`, `apps/backend/src/telemetry/otel.spec.ts:36-45`

**Issue:** Plan 03 requires a span-attribute allowlist (D-23 / T-04.3-07). `isAllowedSpanAttribute` is implemented and unit-tested in isolation, then never passed to `NodeSDK` / a `SpanProcessor` / `getNodeAutoInstrumentations()` options. `initOtel` always registers default auto-instrumentations (HTTP, Undici, ioredis/redis, pg, fs, …). When `OTEL_TRACES_EXPORTER=otlp` (prod collector, D-29), typical leaks:

- `http.url` / `url.full` including query (`ticket`, session params)
- ioredis `db.statement` on BullMQ writes of `HtmlInvoiceFacts.html` (invoice HTML = names, IBAN, line items)

Pino redact does not cover spans. Spec is false-green: it never asserts `initOtel` installs the filter. `initialized = true` is set before `start()`, so a failed start cannot retry.

**Fix:** Wrap the exporter in a processor that drops denied keys; disable statement capture on Redis/PG; do not mark initialized until `start()` succeeds.

```typescript
class AllowlistSpanProcessor implements SpanProcessor {
  constructor(private readonly inner: SpanProcessor) {}
  onStart(span: Span, parent: Context) {
    this.inner.onStart(span, parent);
  }
  onEnd(span: ReadableSpan) {
    for (const key of Object.keys(span.attributes)) {
      if (!isAllowedSpanAttribute(key)) {
        span.attributes[key] = "[redacted]";
      }
    }
    this.inner.onEnd(span);
  }
  shutdown() {
    return this.inner.shutdown();
  }
  forceFlush() {
    return this.inner.forceFlush();
  }
}

// in initOtel, traces === "otlp":
sdkOptions.spanProcessors = [
  new AllowlistSpanProcessor(
    new BatchSpanProcessor(new OTLPTraceExporter()),
  ),
];
sdkOptions.instrumentations = [
  getNodeAutoInstrumentations({
    "@opentelemetry/instrumentation-ioredis": {
      dbStatementSerializer: () => "",
    },
    "@opentelemetry/instrumentation-redis": {
      dbStatementSerializer: () => "",
    },
    "@opentelemetry/instrumentation-pg": {
      requireParentSpan: true,
    },
  }),
];
```

Export a test-only `resetOtelForTests()` or un-set `initialized` in `otel.spec.ts` `afterEach` so the predicate test is not the only coverage.

## Warnings

### WR-01: `GOTENBERG_URL` fail-open default is loopback

**Severity:** WARNING
**File:** `apps/backend/src/pdf/gotenberg.client.ts:21-23`

**Issue:** `REDIS_URL` throws if missing outside test (`pdf.module.ts:14-17`). `GOTENBERG_URL` falls back to `http://127.0.0.1:3000`. Inside Coolify/Compose that is the worker container, not Gotenberg. A missing env does not fail boot; jobs fail later against the wrong origin (and may skip Basic Auth on a different listener).

**Fix:** Require `GOTENBERG_URL` in non-test (same shape as Redis). Keep `DEFAULT_GOTENBERG_URL` only for docs/tests.

```typescript
function gotenbergOrigin(): string {
  const raw = process.env.GOTENBERG_URL?.trim();
  if (!raw) {
    throw new Error("GOTENBERG_URL is required");
  }
  return raw.replace(/\/$/, "");
}
```

### WR-02: Convert fetch has no timeout; BullMQ lock matches Gotenberg 30s with no margin

**Severity:** WARNING
**File:** `apps/backend/src/pdf/gotenberg.client.ts:37-41`
**Also:** `apps/backend/src/pdf/pdf.processor.ts:7-14`, `compose.clared.yml:33`

**Issue:** `fetch` has no `AbortSignal`. Gotenberg `API_TIMEOUT` is 30s. BullMQ default `lockDuration` is 30s. A convert that runs to the server cap can stall the lock, get retried, and double-render. Hung TCP (Gotenberg down) blocks the worker until the platform HTTP timeout.

**Fix:** Abort after 30s (or slightly under lockDuration). Set processor `lockDuration` above that (e.g. 45_000). Optional: `attempts` + backoff for 502/503.

```typescript
const res = await fetch(`${gotenbergOrigin()}${CONVERT_PATH}`, {
  method: "POST",
  headers: { Authorization: basicAuthHeader() },
  body,
  signal: AbortSignal.timeout(30_000),
});
```

```typescript
@Processor(PDF_QUEUE, { lockDuration: 45_000 })
```

### WR-03: Pino redact misses nested `html` (job payload)

**Severity:** WARNING
**File:** `apps/backend/src/telemetry/pino-options.ts:18-37`

**Issue:** D-23: do not log invoice HTML. Paths include exact `"html"` and some `*.iban` / `*.customerName`, but not `*.html` or `data.html`. BullMQ / Nest error logs typically nest `job.data.html`. Exact-path `html` does not redact that.

**Fix:** Add nested paths used by the queue:

```typescript
"html",
"*.html",
"data.html",
"job.data.html",
```

### WR-04: Queue payload not validated; `html` undefined throws TypeError

**Severity:** WARNING
**File:** `apps/backend/src/pdf/pdf.service.ts:10-12`
**Also:** `apps/backend/src/pdf/pdf.processor.ts:8-9`, `apps/backend/src/pdf/gotenberg.client.ts:26-28`

**Issue:** `HtmlInvoiceFacts` is compile-time only. `add()` enqueues anything. Processor passes `job.data.html` through. `undefined.trim()` is a TypeError, not `EmptyHtmlError`. Poison jobs fail with a misleading error and still occupied a worker tick.

**Fix:** Guard at enqueue and at process:

```typescript
add(facts: HtmlInvoiceFacts) {
  if (typeof facts?.html !== "string" || !facts.html.trim()) {
    throw new EmptyHtmlError();
  }
  return this.queue.add("html", { html: facts.html }, { jobId: crypto.randomUUID() });
}
```

Same check at the start of `PdfProcessor.process`.

### WR-05: Release capabilities grant unrestricted SQL execute/load

**Severity:** WARNING
**File:** `apps/desktop/src-tauri/capabilities/default.json:25-28`
**Also:** `apps/desktop/src-tauri/src/lib.rs:58-90`, `apps/desktop/src/components/debug-panel.tsx:44-45`

**Issue:** D-33: SQL smoke is debug-panel only (`DEBUG_PANEL_ENABLED = import.meta.env.DEV`). `default.json` still grants `sql:allow-load`, `sql:allow-execute`, `sql:allow-select`, `sql:allow-close` with no DB URL scope. `sqlite3_auto_extension` applies the SQLCipher key to every connection in the process, so the main webview can open the offline DB (and any other sqlite path the OS allows) without the key ever touching JS (good for D-32, bad for XSS/supply-chain in a release webview). Phase 5 will need SQL; 4.3 production UI does not.

**Fix:** Split a debug capability (or `tauri.conf` debug-only permissions) for `sql:allow-*`. Keep release at no SQL commands until product offline exists; or scope `sql:allow-load` to the `clared-offline.db` URL only.

### WR-06: German span names exported but never used

**Severity:** WARNING
**File:** `apps/backend/src/telemetry/otel.ts:14-16`

**Issue:** D-23 / 04.2 D-54: German internal span names. `SPAN_HTTP_ANFRAGE` and `SPAN_PDF_WARTESCHLANGE` are unused. Auto-instrumentation keeps English span names (`HTTP GET`, ioredis commands). Dead constants look like a completed D-54.

**Fix:** Either set names via a custom HTTP instrumentation `requestHook` / BullMQ span, or delete the constants until a real span is created.

### WR-07: CI never compiles `worker.ts` / `nest build`

**Severity:** WARNING
**File:** `.github/workflows/ci.yml:108-110`
**Also:** `apps/backend/src/worker.ts`, `apps/backend/Dockerfile:29-33`

**Issue:** `backend-unit` runs Jest only. `worker.ts` and `pdf.processor.ts` have no `*.spec.ts`. A type error in the worker entry can merge; only the image build (`test -f dist/worker.js`) catches it, and that runs on `main` / the phase branch, not on arbitrary PRs.

**Fix:** Add `pnpm --filter ./apps/backend exec nest build` (or `tsc -p tsconfig.build.json`) to `backend-unit` after tax-engine build.

### WR-08: Image deploy is not main-only; phase branch stays in `on.push`

**Severity:** WARNING
**File:** `.github/workflows/backend-image.yml:13-16`
**Also:** `.github/workflows/backend-image.yml:136-139`

**Issue:** `on.push.branches` includes `gsd/phase-04.3-infra-prep-for-pdf-offline-audit-gotenberg-uptime-kuma-besze`. Deploy runs whenever `vars.COOLIFY_IMAGE_DEPLOY == 'true'` with no `github.ref == 'refs/heads/main'` guard. Pushes to the leftover branch PATCH+deploy production `clared-api` / `clared-worker`. After merge this is a footgun.

**Fix:** Remove the phase branch from `on.push`. Gate deploy:

```yaml
if: |
  needs.build.result == 'success' &&
  vars.COOLIFY_IMAGE_DEPLOY == 'true' &&
  github.ref == 'refs/heads/main' &&
  (github.event_name != 'workflow_dispatch' || inputs.deploy)
```

Keep `workflow_dispatch` for explicit redeploys.
