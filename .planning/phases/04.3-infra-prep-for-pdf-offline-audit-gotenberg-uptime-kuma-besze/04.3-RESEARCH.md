## Summary

Phase 04.3 is plumbing. Coolify already runs `clared-api`, Authentik, Postgres, Redis, and FaynoSync. This phase **creates** Kuma, Beszel (hub+agent), internal Gotenberg, a second Coolify **application** for the Nest worker (same Dockerfile, different start command), and one observability compose (Grafana + Loki + Tempo + Prometheus + OTel collector). Desktop/backend code only scaffolds pipes: PDF TypeScript contract, BullMQ stub, Pino+OTel, empty SQLCipher DB, debug-panel smokes.

Gotenberg 8.36 has **Basic Auth** (`API_ENABLE_BASIC_AUTH` + `GOTENBERG_API_BASIC_AUTH_USERNAME` / `GOTENBERG_API_BASIC_AUTH_PASSWORD`) and OIDC. There is **no API-key flag** in the official configuration table. Discretion pick: **Basic Auth**. Chromium “no network” is the official **strict whitelist** recipe: `CHROMIUM_DENY_PRIVATE_IPS=true` **and** `CHROMIUM_DENY_PUBLIC_IPS=true` with empty allow-list; Nest never calls `/forms/chromium/convert/url`. A4 is form fields `paperWidth=8.27` `paperHeight=11.7`. Timeout: `API_TIMEOUT=30s`.

Loki’s `lokiexporter` was **removed** from otel-collector-contrib. D-30 path is Pino → `pino-opentelemetry-transport` (OTLP logs) → collector `otlphttp` exporter → Loki `POST /otlp` (`http://loki:3100/otlp`). Keep JSON stdout in parallel (D-23). Local: SDK on, `OTEL_TRACES_EXPORTER=none` and `OTEL_LOGS_EXPORTER=none` (D-24).

Official `tauri-plugin-sql` 2.4.0 Cargo features are `sqlite` / `mysql` / `postgres` only (`# TODO: bundled-cipher etc`). Keep the official plugin (D-31). Enable SQLCipher by Cargo feature-unifying `libsqlite3-sys` (`bundled-sqlcipher-vendored-openssl`); apply `PRAGMA key` in Rust from keychain account **`offline-sqlcipher`** (session stays account **`session`** on service `com.clared.app`).

**Primary recommendation:** Create four Coolify **services** (`clared-kuma`, `clared-beszel`, `clared-gotenberg`, `clared-observability`) plus one Coolify **application** `clared-worker` from the same GitHub app/Dockerfile as `clared-api` with start command `node dist/worker.js` (must **not** run `prisma migrate deploy`). Gate Waves 1 monitors on the Human-needed Telegram + Healthchecks.io checklist.

</research_summary>

<common_pitfalls>
## Common Pitfalls

### Pitfall 1: App containers have no UUID hostname
**What goes wrong:** Kuma `http://yzmje7zsrp1qwtvsd7izjhaf:3000` never resolves. Gotenberg unreachable from worker.
**Why it happens:** Coolify MCP: “App containers have no stable uuid hostname — only databases do.”
**How to avoid:** `custom_network_aliases` = `clared-gotenberg` / `clared-worker`. Postgres/Redis **do** use uuid hostnames (`ypmashcpqnmb3dpxs6nabz4l`, `vvqmbjedd979kkjuwrenghn8`).
**Warning signs:** Kuma DOWN on internal HTTP; worker ECONNREFUSED.

### Pitfall 2: Worker runs Prisma migrate
**What goes wrong:** Two processes migrate; worker crash loops.
**Why it happens:** Dockerfile CMD always migrates then main.
**How to avoid:** Coolify worker `start_command=node dist/worker.js`. Dockerfile still `test -f dist/worker.js` at build.
**Warning signs:** migrate lock errors in worker logs.

### Pitfall 3: Chromium still fetches WAN
**What goes wrong:** Google Fonts / logo URLs leak; D-20 violated.
**Why it happens:** Defaults are **permissive** since Gotenberg 8.32 `[CITED: gotenberg.dev/docs/outbound-url-filtering]`.
**How to avoid:** Both deny-IP flags; no allow-list; Nest never `convert/url`; assets as multipart files.
**Warning signs:** Gotenberg logs outbound HTTP; PDF missing fonts but no bundled files.

### Pitfall 4: Healthchecks period vs cron
**What goes wrong:** False VPS-down alerts.
**Why it happens:** Cron interval ≥ period.
**How to avoid:** Cron every **2 min**; period **5 min**; grace **5 min**. Command ≤ **255** chars (Coolify `scheduled_tasks` varchar).
**Warning signs:** HC down while VPS up.

### Pitfall 5: OTEL export in local compose
**What goes wrong:** Local Nest hangs / noisy failures to missing collector.
**Why it happens:** NodeSDK defaults exporter to OTLP `[CITED: opentelemetry-js NodeSDK README]`.
**How to avoid:** Local `.env`: `OTEL_TRACES_EXPORTER=none` `OTEL_LOGS_EXPORTER=none`. Do **not** add Grafana stack to `compose.clared.yml` (D-24).
**Warning signs:** local boot delay; connection errors to `:4318`.

### Pitfall 6: SQL plugin path vs D-31 app-data
**What goes wrong:** DB lands in AppConfig; capabilities allow `$APPDATA` only.
**Why it happens:** Official SQL docs: path relative to **AppConfig** `[CITED: v2.tauri.app/plugin/sql]`.
**How to avoid:** Absolute `sqlite:` URL under `app.path().app_data_dir()` + `clared-offline.db`.
**Warning signs:** sql load fails ACL; file appears under Application Support config dir.

### Pitfall 7: PII in Pino/OTel
**What goes wrong:** IBAN/customer in Loki.
**Why it happens:** default HTTP instrumentation logs URLs/bodies.
**How to avoid:** pino redact; span attribute allowlist; German internal names (D-23 / D-54).
**Warning signs:** Loki query shows customer strings.

### Pitfall 8: FaynoSync on coolify network
**What goes wrong:** Internal HTTP check fails.
**Why it happens:** FaynoSync prod `connect_to_docker_network: false`.
**How to avoid:** Kuma **public** `https://updates.puzzlessdev.online` only.
**Warning signs:** Kuma DOWN with connection refused internally.

</common_pitfalls>
