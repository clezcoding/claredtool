<decisions>
## Implementation Decisions

### Monitoring — Kuma, Beszel, Healthchecks
- **D-01:** Uptime Kuma and Beszel on Coolify as **public HTTPS subdomains with each app’s built-in login**. — **Reversibility:** costly — DNS + Coolify proxy + bookmarks.
- **D-02:** Kuma targets: `clared-api`, Authentik, Postgres, **plus Redis, Gotenberg, FaynoSync**. Not Garage/side-apps. Grafana HTTPS login page is also a Kuma target (D-28).
- **D-03:** Live down/recovery/TLS alerts to a **Telegram group** (not a private chat). Bot token + invite stay in Coolify env, never git.
- **D-04:** Alert after retries; also recovery; also TLS expiry.
- **D-05:** **No Authentik** (and no Cloudflare Access / IP allowlist) in front of Kuma/Beszel — monitor must stay reachable when Authentik is down.
- **D-06:** Prod monitors only — no staging Kuma in 4.3.
- **D-07:** **No** Kuma public status page — logged-in dashboard only.
- **D-08:** VPS-down detection = **Healthchecks.io** dead-man’s switch. A **Coolify scheduled task** curls the ping URL. Silence → same Telegram group. Do **not** host Kuma/Beszel on Vercel (serverless cannot run them; Hobby cron is once/day).
- **D-09:** Kuma/Beszel data on **Coolify volumes** (SQLite/defaults). Not on Clared Postgres. — **Reversibility:** costly — volume + backup story.
- **D-10:** Pin Kuma/Beszel image tags (not `latest`).

### PDF render pipe — Gotenberg + BullMQ
- **D-11:** Gotenberg **internal only** (Docker/Coolify network). No public host. Desktop never talks to Gotenberg. Nest/worker only. — **Reversibility:** costly — network policy + Kuma check URL.
- **D-12:** Gotenberg **API key or Basic Auth**; secret in Coolify env.
- **D-13:** Official `gotenberg/gotenberg` image. Nest/worker call **Chromium HTML** routes only. LibreOffice stays in the image unused (Word/ZUGFeRD later, not invoices). Do not slim-build without LO in 4.3. Do not replace Gotenberg with Playwright-in-Nest. — **Reversibility:** costly — Coolify service + client contract.
- **D-14:** BullMQ `pdf-generation` queue on existing Redis. **Own Coolify worker app** from day 1. **Same Nest image**, different start command (`main` vs worker). Worker has **no public hostname**. — **Reversibility:** costly — second Coolify app + deploy matrix.
- **D-15:** Local OrbStack: Gotenberg **and** worker in `compose.clared.yml` (with API + Redis).
- **D-16:** Gotenberg: **stdout logs only**, no OTEL on Gotenberg in 4.3.
- **D-17:** Worker sends **multipart HTML** to Chromium. No `convert/url` against the app.
- **D-18:** **No** desktop “generate PDF” in 4.3 — queue + stub + TypeScript contract only. Product generate is Phase 5.
- **D-19:** Pin Gotenberg image tag.
- **D-20:** Chromium **no network** (no URL fetches), render timeout cap, paper **A4**. First-party fonts/images as bundled / multipart assets, not Google Fonts at render time. Custom user templates (later phase): embed assets at save time; optional allowlist — do not open Chromium WAN in 4.3. Post–Phase 6 company logo = **upload + embed** into HTML, not Chromium fetch. — **Reversibility:** costly — Gotenberg Chromium flags + HTML pipeline.

### Backend observability
- **D-21:** Deploy on Coolify (prod): **Grafana OSS + Loki + Tempo + Prometheus**. **No Mimir** (single-VPS Prometheus instead). — **Reversibility:** costly — four services + volumes.
- **D-22:** Grafana: public HTTPS subdomain + **Grafana login**. No Authentik in front.
- **D-23:** Nest **Pino JSON to stdout**. German log/span names (same as 04.2 D-54). No invoice lines, customer names, IBAN, tokens in logs or spans (same class as 04.2 D-40).
- **D-24:** OpenTelemetry SDK **on** with **HTTP request traces** (no PII in span attributes). Local: SDK on, **export off** (or console). Collector/Tempo/Grafana **not** in local compose.
- **D-25:** Pin Grafana, collector, Loki, Tempo, Prometheus image tags.
- **D-26:** Retention **~7 days** for logs/traces/metrics.
- **D-27:** Coolify volumes for Grafana, Loki, Tempo, Prometheus.
- **D-28:** Kuma HTTP-checks Grafana login page (200, not an authenticated crawl). **No** Grafana-alerting to Telegram — Telegram stays Kuma + Healthchecks only.
- **D-29:** **API and worker** both send OTLP (traces + logs) to the collector. Gotenberg does not (D-16).
- **D-30:** Pino → **OTLP logs** → collector → Loki. No Promtail/Alloy sidecar; do not scrape Coolify log files as the contract.

### Desktop scaffold
- **D-31:** `tauri-plugin-sql`: migrations dir + **empty** schema (one `_init` dummy). File in app-data: `clared-offline.db`. **SQLCipher now** on that empty DB. — **Reversibility:** costly — plugin + key story; plaintext later would be a migration.
- **D-32:** SQLCipher key in **OS keychain** (with session keys), not store-JSON, not env file.
- **D-33:** Official `dialog` + `fs` + `sql`: install + **smoke in debug panel only** (Cmd/Ctrl+D; dead in release). No product save/share UI. Extends 04.2 D-47 for 4.3 smokes.
- **D-34:** `fs` allowlist: **app-data + temp only**. User-chosen paths only via **dialog**. No silent Downloads/home.
- **D-35:** `tauri-plugin-sharekit`: **install without SUS gate** (user: community crate is fine). Smoke in debug panel. PDF drag-out remains Phase 5 CrabNebula `tauri-plugin-drag` (04.2), not sharekit and not blocked dragout.

### Claude's Discretion
- Exact Coolify service names and subdomain slugs (`kuma.`, `beszel.`, `grafana.`, etc.) within D-01/D-22.
- Telegram group display name (default “Clared ops” if unset).
- Exact pinned image versions (research current stable; D-10/D-19/D-25 require pins).
- Healthchecks.io period/grace; Coolify cron interval (must be shorter than period).
- Gotenberg Chromium timeout seconds and disable-network flag names.
- SQLCipher key generation/rotation on first launch.
- Worker start command module path within the same Nest image.
- Gotenberg auth: API key vs Basic — pick one and document env names.

</decisions>
