# Phase 04.6: Takumi+pdfcn PDF Engine Cutover - Context

**Gathered:** 2026-09-05
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace Gotenberg/Chromium completely with Takumi + pdfcn **Invoice Minimal** as the sole invoice PDF renderer. Nest API produces visual PDF bytes in-process from InvoiceModel + TaxDecision. No dual pipeline, no Gotenberg fallback, no BullMQ `pdf-generation` hop. Phase 4.7 attaches e-invoice XML. Phase 5 downloads/views.

**In scope:**

1. `@clared/pdf-templates` (JSX) + `InvoicePdfService` in Nest — `takumi-pdf` `render()`, pdfcn Invoice Minimal copy-paste, Crafted Minimal tokens, A4, DE/EN, TaxDecision text block.
2. Complete Gotenberg removal: Coolify `clared-gotenberg`, compose `gotenberg`, `gotenberg.client.ts`, `GOTENBERG_*`, Kuma Gotenberg monitor, `/health/ready` Gotenberg probe, Chromium HTML convert path.
3. Complete PDF job-pipe removal: BullMQ `pdf-generation`, `@nestjs/bullmq`/`bullmq`, `PdfProcessor`, `clared-worker` (Coolify + compose + Dockerfile worker stage + GHA worker image/deploy), `worker.ts` / `WorkerModule`.
4. Dockerfile copies/builds pdf-templates; wasm in API image; GHA + `coolify-deploy-nest.sh` API-only (04.5 D-03 API→worker order superseded).
5. Vendored Inter + Instrument Serif WOFF2. npm deny-list. Ops addendum. Fixtures: Invoice+TaxDecision → `%PDF-` bytes, no Chrome, no XML attachment.

**Out of scope (non-negotiable):**

- PDF-01 desktop download/view, AUDT-01, OFFL-01, public generate HTTP route (Phase 5)
- Factur-X / ZUGFeRD XML, XRechnung, PDF/A-3 embedding, PDF/UA-1 `tagged: "ua1"` (Phase 4.7 / never for UA-1)
- Redis removal (session KV stays); MAIL-01 queue (v2)
- Desktop Settings UI for locale / vatLine (later settings / Phase 5)
- Logo upload, Entity IBAN/BIC, HRB/Geschäftsführer/Handelsregister fields
- Feature-toggle dual-run; HTML/Handlebars invoice templates; Forme registry; npm packages named `takumi`, `pdfcn`, `forme`, `@takumi-rs/core`

</domain>

<decisions>
## Implementation Decisions

### Engine (founder + research locks — do not re-open)
- **D-01:** Sole renderer is `takumi-pdf` + pdfcn **Invoice Minimal** (`npx shadcn@latest add @pdfcn/takumi/invoice-minimal`), restyled to Crafted Minimal tokens. Page `size: "a4"` (matches 04.3 A4 8.27×11.7). — **Reversibility:** one-way — Coolify Gotenberg and the Chromium HTML contract are deleted in this phase; going back is a new engine phase.
- **D-02:** Render **synchronously in the Nest API**. Drop BullMQ queue `pdf-generation` and `clared-worker` with Gotenberg. Redis stays for session KV. MAIL-01 may add a queue in v2. — **Reversibility:** one-way — worker image, GHA worker deploy, and Coolify worker app are removed.
- **D-03:** No feature toggle, no Gotenberg fallback, no dual-run, no HTML/Handlebars invoice templates. `HtmlInvoiceFacts.html` dies; input is InvoiceModel + TaxDecision (+ render knobs).
- **D-04:** No public generate HTTP route in 4.6 — service + fixtures only. PDF-01 download/view stays Phase 5.
- **D-05:** PDF/UA-1 off (`tagged: "ua1"` not set). Forme registry never.
- **D-06:** Factur-X Comfort CII, XRechnung, and PDF/A-3b embed (`pdfa: "3b"` + attachments + XMP) are **Phase 4.7**. 4.6 visual PDF has **no** XML attachment.
- **D-07:** Fonts vendored in the image (Inter + Instrument Serif WOFF2). No `googleFonts()` network fetch at Coolify render time (extends 04.3 D-20).
- **D-08:** Pin `takumi-pdf` + `@takumi-rs/helpers` + `react` on pdf-templates. Do not add npm `takumi`, `pdfcn`, `forme`, or `@takumi-rs/core`.
- **D-09:** Dockerfile COPY+build `@clared/pdf-templates`; wasm must land in the API image; drop `dist/worker.js` assert and `FROM build AS worker`. GHA + `coolify-deploy-nest.sh` are API-only (no `*-worker` tag, no worker Trivy/SBOM/cosign, no `COOLIFY_APP_WORKER`). **04.5 D-03/D-04 worker half is superseded.**
- **D-10:** Ops docs are an **addendum** (04.5 D-16 pattern). Do not rewrite 04.3 PLAN/SUMMARY history. Update 04.3-PDF-OPS / MONITOR-OPS + `.env.example` without `GOTENBERG_*`.

### TaxDecision on paper
- **D-11:** TaxDecision legal text is a **dedicated block under totals**, before the footer — not footer-only, not duplicated in the footer.
- **D-12:** Print only `legal_reference`, plus the reverse-charge sentence when `reverse_charge_flag` is true. Do **not** print `applied_rule_id`, `applied_rule_version`, `audit_trace`, or `invoice_text_block_id` (lookup key). Rate belongs in the VAT totals line when tax is shown. Audit fields stay AUDT-01 / Phase 5.

### Header, lines, footer
- **D-13:** No logo image and no gray “Logo” placeholder. Header uses **`Entity.name` as text** until Phase 6 upload+embed.
- **D-14:** No Zahlungsblock (IBAN/BIC) in 4.6. Entity schema has no bank fields. Do not invent a dummy IBAN in fixtures.
- **D-15:** Seller/buyer from Entity + Customer: `name`, `address`, `vatId`, `country`, `legalForm` (seller). Line items from `InvoiceItem` (`bezeichnung`, `menge`, `einzelpreis`, `netto`). Header also shows invoice `number`, `date`, and `dueDate` when set.
- **D-16:** Footer is **compliant-possible with current schema**: `Page n of m` plus one line `Entity.name · legalForm · country`. Full Impressum (HRB, Geschäftsführer, Handelsregister) waits on Entity stammdaten fields — not 4.6.
- **D-17:** Fixtures are **issued-looking** (number, date, due). **No ENTWURF watermark.** Draft overlay is Phase 3/5 product UI, not the engine proof.

### Locale, numbers, VAT line
- **D-18:** Number and date format follow `locale`: `de` → `1.234,56 €` and `TT.MM.JJJJ`; `en` → `€1,234.56` and `YYYY-MM-DD`. Use `Intl`. Never always-DE on an EN page; never ISO-only on a DE page.
- **D-19:** When `invoice_tax_shown === false`, never print a fake 19% VAT amount. The company will later choose `vatLine: "omit"` (no VAT amount line; totals = net; legal block carries the sentence) vs `"zero"` (line “MwSt 0,00” plus legal block). `10c` (always 19%) is forbidden.
- **D-20:** Product intent: locale and `vatLine` are **per-company settings**, defaulted from country, overridable in a future Settings UI. **Not built in 4.6** (no desktop UI, no Prisma columns).
- **D-21:** 4.6 contract: render knobs `locale: "de" | "en"` and `vatLine: "omit" | "zero"` plus helper `defaultsFromCountry(entity.country)`. Fixtures set knobs explicitly.
- **D-22:** Country defaults: `DE`/`AT` → `locale=de`, `vatLine=omit`. Any other country → `locale=en`, `vatLine=omit`. No silent `GB` → `zero` special case; `zero` is a later override.

### Fixtures
- **D-23:** Three CI fixtures, all `%PDF-`, no Chrome, no XML: (1) DE locale, DE B2B 19%, tax shown; (2) EN locale, **same facts** as (1); (3) DE reverse-charge (`invoice_tax_shown: false`, `reverse_charge_flag: true`, shape of `EU_TO_EU_B2B_GOODS_INTRACOMM`). Optional extra: one RC fixture with `vatLine: "zero"` only if cheap — not required.

### Cutover, health, errors
- **D-24:** Same execute wave: API image green (ready **without** Gotenberg key) → Coolify MCP/CLI deletes `clared-gotenberg` (`iokfnlnzidksuvrabx7ixxiv`) and `clared-worker` (`vwhnsihwpezppgwepvwxrk2h`); Kuma Gotenberg monitor **deleted** (not paused); local compose drops `gotenberg` + `worker` in the **same PR**. No human prod-gate that leaves corpses running. Rollback = image pin, not re-enable Gotenberg. Coolify via `user-coolify` MCP + `coolify` CLI only; Kuma via `project-0-claredtool-uptime-kuma` MCP.
- **D-25:** `/health/ready` drops the Gotenberg indicator entirely. Ready = Postgres + Redis + build-sha. No Takumi wasm ping. No stub `pdf: { engine: "takumi" }`. Engine proof is the fixtures, not Ready. Deploy poll of `/health/ready` (04.5) stays valid without a PDF probe. — **Reversibility:** costly — Kuma and Coolify deploy gates currently include the Gotenberg check.
- **D-26:** Render failure **throws** (fail-closed). No empty `PdfBytes`. No Result-type on the internal service. Exception messages must not contain PII (names, IBAN, invoice lines) — 04.3 D-23.

### Claude's Discretion
- `PdfRenderer` vs per-call `render()` (font cache is fine; research prefers reuse).
- Exact Crafted token mapping on copied pdfcn source; keep layout flat (Takumi CSS subset, no blur).
- Fixture seller/buyer display names and addresses (plausible DE GmbH, not production PII).
- Pin exact `takumi-pdf` version at plan/execute time (`0.14.1` was current at research).
- Whether to include a fourth `vatLine: "zero"` fixture.
- Wave-0 Docker build that `render()`s a fixture inside the image (research: prove wasm lands).

</decisions>
