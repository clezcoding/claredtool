## Summary

Takumi/pdfcn-Cutover (WASM `takumi-pdf@0.14.2`, Worker/Gotenberg entfernt, API-only Deploy, Nest `InvoicePdfService`) ist weitgehend konsistent. Lockfile-Pins stimmen; Fonts + OFL vorhanden; Ready ohne Chromium passt zu D-25.

Ein **BLOCKER**: Redis-Ready-Check via `Promise.race` ohne Absicherung der unterlegenen `ping()`-Promise — unter Node-Default `unhandledRejection=throw` kann das den API-Prozess killen, genau wenn Ready/Deploy/Monitore Redis-Latenzen sehen.

Weitere Lücken: numerische Coercion (`""` → `0`), fehlende Rechen-/Vorzeichen-Guards, hartcodierte Deploy-Health-URL, e2e Ready ohne `build.sha`, Compose/CI DB-Version-Skew, kein Renderer-Recreate nach WASM-Panic.

## Critical Issues

### CR-01: Redis ready `Promise.race` orphan rejection can crash API

**File:** `apps/backend/src/health/health.controller.ts:35-52`
**Issue:** Ready-Indikator raced `this.redis.ping()` gegen ein 400ms-Timeout. Gewinnt das Timeout, bleibt `ping()` pending. Rejectet ioredis später (Socket-Fehler nach Hang), entsteht eine **unhandled rejection**. Unter Node 24 Default (`--unhandled-rejections=throw`) beendet das den Nest-Prozess. Coolify-Deploy pollt `/health/ready` aggressiv; genau bei kränkelndem Redis ist Crash-Risiko am höchsten.
**Fix:**
```typescript
async (): Promise<HealthIndicatorResult> => {
  const timeoutMs = 400;
  let timer: ReturnType<typeof setTimeout> | undefined;
  const ping = this.redis.ping().then(
    (v) => v,
    () => {
      throw new Error("Redis ping failed");
    },
  );
  // Prevent orphan rejection if timeout wins the race.
  ping.catch(() => undefined);
  try {
    await Promise.race([
      ping,
      new Promise<never>((_, reject) => {
        timer = setTimeout(
          () => reject(new Error("Redis ping timeout")),
          timeoutMs,
        );
      }),
    ]);
  } finally {
    if (timer !== undefined) clearTimeout(timer);
  }
  return { redis: { status: "up" } };
},
```
Besser langfristig: ioredis-Command-Timeout oder `Promise.race` mit explizitem settled-Flag.

## Warnings

### WR-01: Empty-string numerics coerce to 0 and pass validation

**File:** `apps/backend/src/pdf/invoice-pdf.service.ts:42-61,90-98`
**Issue:** `toNum("")` → `Number("")` → `0`, und `Number.isFinite(0)` ist true. Leere Prisma/String-Felder für `menge` / `einzelpreis` / `netto` / `invoice_tax_rate` werden zu gültigen Nullen und erzeugen PDF statt `RenderFailedError`.
**Fix:** Nach Coercion rejecten wenn Original-String leer/whitespace, oder `toNum` nur für `number | Decimal`-ähnliche Werte erlauben:
```typescript
function toNum(value: unknown): number {
  if (typeof value === "number") return value;
  if (typeof value === "string" && value.trim() === "") return Number.NaN;
  if (value == null) return Number.NaN;
  return Number(String(value));
}
```
Zusätzlich `menge > 0` (oder `>= 0` bewusst dokumentieren) erzwingen.

### WR-02: Negative line amounts / tax rate accepted

**File:** `apps/backend/src/pdf/invoice-pdf.service.ts:90-98`
**Issue:** `isFiniteNumber` erlaubt negative `menge` / `einzelpreis` / `netto` / `invoice_tax_rate`. Nest rendert dann negativ bewertete Rechnungen ohne Fail-closed.
**Fix:** Guard ergänzen, z.B. `item.menge > 0 && item.einzelpreis >= 0 && item.netto >= 0` und `tax.invoice_tax_rate >= 0` (Gutschriften bewusst separater Pfad).

### WR-03: Deploy health poll hardcodes production URL

**File:** `.github/scripts/coolify-deploy-nest.sh:144-145`
**Issue:** Poll trifft fest `https://clared-api.puzzlessdev.online/health/ready`. Domain-/Env-Wechsel oder Preview bricht Deploy/Rollback-Logik, obwohl `COOLIFY_URL` / App-UUID bereits parametrisiert sind.
**Fix:** URL aus `vars` lesen (z.B. `API_HEALTH_URL`) und im Workflow setzen; Mock-Tests Stub weiter auf Substring `health/ready` matchen.

### WR-04: e2e Ready omits `build.sha` contract used by deploy

**File:** `apps/backend/test/health.e2e-spec.ts:46-53`
**Issue:** Deploy-Skript verlangt `details.build.sha` / `info.build.sha` === `SHA_TAG`. e2e prüft nur `postgres`/`redis` und akzeptiert 200|503 — Regression die `build`-Indicator entfernt, bleibt grün, Prod-Deploy rollt zurück.
**Fix:**
```typescript
it("GET /health/ready includes build.sha when 200", async () => {
  const res = await request(app.getHttpServer()).get("/health/ready");
  expect([200, 503]).toContain(res.status);
  if (res.status === 200) {
    const sha =
      res.body?.details?.build?.sha ?? res.body?.info?.build?.sha;
    expect(sha).toBe("e2e-health-build-sha");
  }
});
```

### WR-05: Local compose DB/Redis majors diverge from CI

**File:** `compose.clared.yml:3,19` vs `.github/workflows/ci.yml:245,259`
**Issue:** Lokal `postgres:18-alpine` + `redis:8-alpine`; CI pinned `postgres:16` + `redis:7`. Migrate/Verhalten kann lokal grün und in CI (oder umgekehrt auf Coolify) brechen.
**Fix:** Compose auf dieselben Major-Versionen wie CI/Prod pinnen (Digest optional), oder dokumentiertes bewusstes Upgrade mit CI-Mitziehplan.

### WR-06: Shared `PdfRenderer` never recreated after failure

**File:** `packages/pdf-templates/src/render-invoice.ts:56-68,208-222`
**Issue:** Ein Prozess-weiter `PdfRenderer` + Lock. Nach WASM-Panic/internem Fehler fängt `catch` nur `Render fehlgeschlagen` — Instanz wird nicht ersetzt. Folgerender können dauerhaft failen bis Process-Restart.
**Fix:** Bei Render-Fehler Renderer droppen und neu instanziieren:
```typescript
} catch {
  try { renderer.free?.(); } catch { /* ignore */ }
  // reassign module-level renderer = new PdfRenderer()
  throw new Error(RENDER_FAILED);
}
```
(API an `takumi-pdf` `free()` anpassen.)
