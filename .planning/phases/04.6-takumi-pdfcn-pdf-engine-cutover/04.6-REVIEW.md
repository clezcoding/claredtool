## Critical Issues

### CR-01: Printed VAT rows can fail arithmetic (unrounded float tax/total)

**File:** `packages/pdf-templates/src/render-invoice.ts:142-169`
**Issue:** `taxAmount` and `total` use raw floats (`subtotal * (rate / 100)`, `subtotal + taxAmount`), then each value is passed through `Intl.NumberFormat` independently. Half-cent cases produce **internally inconsistent** paper. Proven with Node `Intl` de-DE:

- net `45.50` @ 19% → tax raw `8.645` formats **8,65 €**; total raw `54.1449…` formats **54,14 €**
- Correct commercial path (round tax to 2 dp, then add): tax **8,65 €**, total **54,15 €**
- Printed implication: **45,50 + 8,65 ≠ 54,14**

Legal invoice PDF totals must add. This fires on valid finite inputs (no need for NaN).
**Fix:** Round to EUR cents before format (or compute in integer cents). Prefer: round tax first, then `total = net + roundedTax`.

```typescript
function roundEur(n: number): number {
  return Math.round((n + Number.EPSILON) * 100) / 100;
}

const subtotal = roundEur(
  model.items.reduce((sum, line) => sum + Number(line.netto), 0)
);
const rate = Number(tax.invoice_tax_rate) || 0;
const showTax = tax.invoice_tax_shown === true;
const taxAmount = showTax ? roundEur(subtotal * (rate / 100)) : 0;
const total = roundEur(subtotal + taxAmount);
```

Add a unit case for `45.50` @ 19% asserting de formats tax `8,65` and total `54,15`.

### WR-01: Package `test` script skips format-money and defaults-from-country suites

**File:** `packages/pdf-templates/package.json:9`
**Issue:** `"test": "jest --testPathPatterns=render-invoice"` only. CI runs `pnpm --filter @clared/pdf-templates test` (`.github/workflows/ci.yml:220`). `jest --listTests` under that pattern returns only `render-invoice.spec.ts`; `format-money.spec.ts` and `defaults-from-country.spec.ts` (D-18 / D-22) never run in CI despite existing. Manual verification used a broader pattern; the package script does not.
**Fix:**

```json
"test": "jest"
```

Or:

```json
"test": "jest --testPathPatterns='format-money|defaults-from-country|render-invoice'"
```

Relying on `jest.config.cjs` `testRegex: ".spec.ts$"` is enough if the pattern is dropped.

### WR-02: Nest input validation accepts non-finite numbers

**File:** `apps/backend/src/pdf/invoice-pdf.service.ts:56-71`
**Issue:** Checks `typeof … === "number"` only. `NaN` and `Infinity` pass (`typeof NaN === "number"`). In `render-invoice.ts:146`, `Number(tax.invoice_tax_rate) || 0` collapses `NaN` to **0%** while `invoice_tax_shown` can still be true → PDF shows **MwSt 0 %** with valid `%PDF-` magic (fail-open on bad math). Same for line `netto` / `einzelpreis` → `formatMoney(NaN)` can still yield a PDF.
**Fix:** Reject non-finite values in `validateInput`:

```typescript
function isFiniteNumber(value: unknown): value is number {
  return typeof value === "number" && Number.isFinite(value);
}
// use for invoice_tax_rate, menge, einzelpreis, netto
```

Optionally mirror a light guard in `renderInvoice` for direct package callers.

### WR-03: Prisma `Decimal` line amounts will always fail Nest typeof gates

**File:** `apps/backend/src/pdf/invoice-pdf.service.ts:63-71` (call boundary; schema evidence `apps/backend/prisma/schema.prisma:68-70`)
**Issue:** Line amounts are `Decimal @db.Decimal(12, 2)`. `typeof decimal !== "number"`, so any Phase 5 caller that passes Prisma rows straight into `InvoicePdfService.render` gets `RenderFailedError` with no coercion. Fail-closed is correct; missing boundary conversion is an easy integration footgun immediately after this cutover.
**Fix:** Coerce at the service edge (or a tiny mapper used by the future download route):

```typescript
const toNum = (v: unknown): number =>
  typeof v === "number" ? v : Number(String(v));
// after coerce, require Number.isFinite
```

### IN-01: Dead `RenderFailedError` branch in Nest catch

**File:** `apps/backend/src/pdf/invoice-pdf.service.ts:101-106`
**Issue:** `renderInvoice` throws plain `Error("Render fehlgeschlagen")`, never `RenderFailedError`. The `instanceof RenderFailedError` arm is unreachable for the package path (validation throws before the try).
**Fix:** Drop the branch, or make `@clared/pdf-templates` throw a shared error type Nest re-exports.

### IN-02: Process-wide `PdfRenderer` singleton

**File:** `packages/pdf-templates/src/render-invoice.ts:56`
**Issue:** One module-level `PdfRenderer` shared across concurrent Nest requests. Fine if Takumi WASM is re-entrant; undocumented if not (corrupted bytes under load could still pass `%PDF-` magic).
**Fix:** Confirm Takumi concurrency contract; if unsafe, instantiate per `renderInvoice` call or serialize with a mutex.
