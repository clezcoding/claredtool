## Summary

Takumi+pdfcn Cutover ist strukturell sauber: Gotenberg/Worker raus, Sync-`InvoicePdfService` + `@clared/pdf-templates`, Fail-closed `RenderFailedError`, Deploy API-only, Health ohne Chromium (D-25). Kein Critical mit Beweis.

Hauptlücken: Validierung erlaubt negative Beträge/Sätze, keine Bounds gegen Render-DoS, keine Mengen×Preis↔Netto-Abstimmung, fettes Docker-Image inkl. möglicher `tmp/`-Fixtures, und Ready prüft den PDF-Pfad nicht. `pnpm-lock.yaml` nur Pin-Spotcheck (`takumi-pdf@0.14.2`, `@takumi-rs/helpers@2.13.6`); WOFF2 nur Presence+OFL.

## Warnings

### WR-01: Negative Mengen/Preise/Steuersätze passieren Validierung

**File:** `apps/backend/src/pdf/invoice-pdf.service.ts:90-98`
**Issue:** `isFiniteNumber` akzeptiert negative Werte. Negatives `invoice_tax_rate`, `menge`, `einzelpreis` oder `netto` erzeugt druckbare Nonsense-MwSt/Totals statt Fail-closed.
**Fix:** Nach Finite-Check strikt nicht-negativ (und Rate in erwarteter Domäne, z. B. `0…100`):

```typescript
if (
  !isFiniteNumber(item.menge) ||
  item.menge < 0 ||
  !isFiniteNumber(item.einzelpreis) ||
  item.einzelpreis < 0 ||
  !isFiniteNumber(item.netto) ||
  item.netto < 0
) {
  throw new RenderFailedError();
}
// tax.invoice_tax_rate: isFiniteNumber && >= 0 && <= 100
```

### WR-02: Keine Obergrenze für Positionen / String-Längen

**File:** `apps/backend/src/pdf/invoice-pdf.service.ts:81-82`
**Issue:** `items.length === 0` ist verboten, aber unbegrenzt viele/lange Zeilen sind erlaubt. Sync-Render hält globalen `PdfRenderer`-Lock (`render-invoice.ts:56-68`) — ein fetter Request blockiert alle PDF-Jobs. Service hängt bereits in `AppModule` / `PdfModule`.
**Fix:** Harte Caps an der Service-Kante, z. B. `items.length <= 200`, `bezeichnung.length <= 500`, Adressfelder begrenzt; bei Überschreitung `RenderFailedError`.

### WR-03: Mengen×Preis vs. Netto nicht abgestimmt

**File:** `packages/pdf-templates/src/render-invoice.ts:160-186`
**Issue:** Tabelle zeigt `menge` / `einzelpreis` / `netto` unabhängig; Subtotal summiert nur `netto`. Inkonsistente Input-Daten (2×100, Netto 150) drucken widersprüchliche Rechnung.
**Fix:** In `validateInput` (Service) oder `renderInvoice` fail-closed:

```typescript
if (roundEur(item.menge * item.einzelpreis) !== roundEur(item.netto)) {
  throw new RenderFailedError(); // bzw. Error(RENDER_FAILED)
}
```

### WR-04: Docker-Context kann `packages/pdf-templates/tmp/` einbacken

**File:** `apps/backend/Dockerfile:23` (Context: `.dockerignore`)
**Issue:** `COPY packages/pdf-templates` kopiert alles außer `.dockerignore`-Treffern. `tmp/` ist nur in `packages/pdf-templates/.gitignore`, nicht in `.dockerignore`. Lokale Builds nach Fixture-Tests legen Sample-PDFs in das API-Image.
**Fix:** In `.dockerignore` ergänzen:

```
packages/pdf-templates/tmp
**/tmp
```

### WR-05: API-Image ohne `--prod` / Single-Stage mit Build-Toolchain

**File:** `apps/backend/Dockerfile:20-57`
**Issue:** `pnpm install` ohne `--prod` + `FROM build AS api` shippt DevDeps (Jest, Nest CLI, TS), Full-Source und Build-Caches in Runtime. Vergrößert Angriffsfläche und Image-Drift; Worker-Stage entfernt, aber kein schlankes Runtime-Stage nachgezogen.
**Fix:** Multi-stage: Build-Stage unverändert; Runtime-Stage nur `node_modules` production (oder `pnpm deploy`), `dist/`, Prisma-Engines, `packages/pdf-templates/{dist,fonts}`, non-root CMD.

### WR-06: Opaque Catch + Ready prüft PDF nicht

**File:** `apps/backend/src/pdf/invoice-pdf.service.ts:129-131`, `packages/pdf-templates/src/render-invoice.ts:220-222`, `apps/backend/src/health/health.controller.ts:32-59`
**Issue:** Jeder Render-Fehler (fehlende Fonts, WASM, OOM) wird zu `Render fehlgeschlagen`. `/health/ready` = Postgres+Redis+build — Deploy-Poll (`coolify-deploy-nest.sh:136-164`) kann grün sein, während erster PDF-Call hart failt.
**Fix:** Startup/`onModuleInit`: Fonts `access` + einmaliger Smoke-Render (oder lightweight `PdfRenderer` ping); Ready-Indicator `pdf: { status: "up" }`. Interne Logs dürfen `cause` behalten, Client-Message bleibt generisch (D-26).

### WR-07: Country-Defaults nur bei exaktem ISO DE/AT

**File:** `packages/pdf-templates/src/defaults-from-country.ts:8-14`
**Issue:** Nur `DE`/`AT` nach `trim().toUpperCase()`. Prisma `country` ist freier `String`. `"Deutschland"`, `"de-DE"`, Tippfehler → still `en` + `omit` trotz DE-Seller — falsche Labels/Datumsformat ohne Fehler.
**Fix:** ISO-3166-alpha-2 validieren (`/^[A-Z]{2}$/`) in `validateInput`; unbekannte Codes fail-closed oder explizite Allowlist; Defaults nur auf validierten Codes.
