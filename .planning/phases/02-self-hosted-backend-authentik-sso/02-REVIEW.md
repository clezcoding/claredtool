## Critical Issues

### CR-01: Logout is recorded as `lastRequest`, so the next redeem logs the user back out

**File:** `apps/desktop/src/auth/api.ts:38-47`, `75-86`; `apps/desktop/src/auth/session-provider.tsx:89-100`
**Issue:** D-31 retries the last `apiFetch` after a successful ticket redeem. `logoutSession` is the **only** production caller of `apiFetch` (invoice/entity clients are not in this phase). It therefore leaves `lastRequest = { path: "/auth/logout", init: { method: "POST" } }`. After Abmelden, the next Anmelden path is: `redeemTicket` (raw `fetch`) → `fetchMe` (raw `fetch`, does not touch `lastRequest`) → `applySession` → `replayLastRequest(nextToken)`. Replay POSTs `/auth/logout` with the **new** Bearer. Nest DELs `session:{newToken}`. UI is already `signed` with `me` from `fetchMe`; Redis session is gone. Next real API call 401s (or the user sits on a dead keychain token). `replayLastRequest(...).catch(() => undefined)` swallows the 200. First-ever login is fine (`lastRequest` unset); **every login after a successful logout is broken.**
**Fix:** Do not track logout (same pattern as `fetchMe`). Clear `lastRequest` on sign-out. Skip replay when the stored path is `/auth/logout`.

```ts
export async function logoutSession(
  token: string,
): Promise<{ endSessionUrl: string }> {
  const res = await fetch(`${BASE}/auth/logout`, {
    method: "POST",
    headers: { Authorization: `Bearer ${token}` },
  });
  if (!res.ok) {
    throw new Error(`logoutSession failed: ${res.status}`);
  }
  lastRequest = undefined;
  return (await res.json()) as { endSessionUrl: string };
}
```

## Warnings

### WR-01: 401 handler leaves the shell (`unsigned`), violating D-31

**File:** `apps/desktop/src/auth/session-provider.tsx:174-191`; `apps/desktop/src/App.tsx:114-116`
**Issue:** D-31: on 401, **shell stays**, banner, login window, retry last request after success. `setOnUnauthorized` deletes the keychain (good vs old WR-04) then `setState("unsigned")`, which unmounts `AppShell` and shows `LoginGate`. Banner can still render on the gate, but the signed-in chrome and in-progress invoice UI are gone. When Phase 3 starts calling `apiFetch`, every expiry will kick the operator to the full-screen gate instead of a sticky shell + retry.
**Fix:** Stay `signed` (or a dedicated reauth flag). Keep `me` for chrome. Clear `tokenRef` so further calls do not keep using the dead Bearer. Set `bannerKind: "unauthorized"`, open the login window, redeem, then `applySession` + `replayLastRequest`. Do not route through `LoginGate` for a mid-session 401.

### WR-02: Closing the login window never shows „Anmeldung abgebrochen“ (D-20)

**File:** `apps/desktop/src-tauri/src/lib.rs:113-179`; `apps/desktop/src/auth/session-provider.tsx:100-106`
**Issue:** D-20: cancel/timeout on main shows banner „Anmeldung abgebrochen“ with retry. `bannerKind === "cancel"` is set only in `redeem`'s `catch` (ticket 401/network). `open_login_window` has no `on_window_event` / `Destroyed` / `CloseRequested` handler. User clicks Anmelden, closes the OS titlebar — no event reaches React. Gate stays unchanged; no banner, no retry affordance beyond the existing Anmelden button.
**Fix:** On login-window close without a ticket emit, `emit` e.g. `login-cancelled` to `main`. Provider sets `bannerKind: "cancel"`. Ignore close after a successful `ticket-received`.

```rust
.on_window_event(|window, event| {
    if let tauri::WindowEvent::Destroyed = event {
        let _ = window.app_handle()
            .get_webview_window("main")
            .map(|main| main.emit("login-cancelled", ()));
    }
})
```

### WR-03: Confidential-client `SECRET` defaults to empty string

**File:** `apps/backend/src/auth/oidc.ts:77-82`, `102-107`
**Issue:** `REDIS_URL` and `CORS_ORIGINS` fail closed. `SECRET` uses `process.env.SECRET ?? ""` into `ClientSecretPost`. Coolify omitting `SECRET` still boots Nest. Token exchange then runs a confidential client with an empty secret (Authentik reject / misconfigured public client). Same class as the old Redis fail-open, on the OIDC credential.
**Fix:** Require `SECRET` whenever `testModeEnabled()` is false, at discovery time (both `beginAuthorization` and `authorizationCodeGrant`).

```ts
function clientSecret(): string {
  const secret = process.env.SECRET;
  if (!secret) {
    throw new Error("SECRET is required");
  }
  return secret;
}
```

### WR-04: Catch-all `401` likely shadows Swagger (`/api/docs`, `openapi.json`)

**File:** `apps/backend/src/http/catch-all.controller.ts:4-8`; `apps/backend/src/main.ts:17-27`
**Issue:** D-05 and D-10 together: Swagger at `/api/docs` + `openapi.json`, everything else 401. `CatchAllController` `@All("{*path}")` is a Nest route that answers 401. `SwaggerModule.setup` mounts Express handlers after `NestFactory.create`; Nest's request handler typically consumes the request first, so `/api/docs` and `/openapi.json` return 401 instead of the document. Phase-2 HTTP surface then has no reachable OpenAPI.
**Fix:** Exclude those paths from the catch-all (dedicated public controllers, or a guard that skips `api/docs` / `openapi.json`), or mount Swagger through Nest so it wins specificity.

```ts
@All("{*path}")
unmatched(@Req() req: { url?: string }): never {
  const path = req.url?.split("?")[0] ?? "";
  if (path.startsWith("/api/docs") || path === "/openapi.json") {
    throw new NotFoundException();
  }
  throw new UnauthorizedException();
}
```

Prefer registering Swagger as real Nest routes so the catch-all never sees them.

## Info

### IN-01: `AUTH_TEST_MODE=1` is only refused when `NODE_ENV === "production"`

**File:** `apps/backend/src/auth/oidc.ts:51-57`
**Issue:** Production image sets `NODE_ENV=production`, so Coolify-as-shipped is guarded. A preview/staging app with `NODE_ENV=development` (or unset, if the image ENV is overridden to empty) plus a copied `.env.example` that someone flips to `AUTH_TEST_MODE=1` still mints `clared-owner` with no Authentik.
**Fix:** Also refuse when `SECRET` is set (real IdP) or unless `NODE_ENV === "test"`. Keep the unit test that production throws.

### IN-02: `prisma.config.ts` invents a dummy `DATABASE_URL` if unset

**File:** `apps/backend/prisma.config.ts:4-7`; `apps/backend/Dockerfile:30`
**Issue:** Nest `PrismaService` fail-closes. Image `CMD` runs `prisma migrate deploy` first; that loads `prisma.config.ts`, which **assigns** `postgresql://prisma-generate:unused@127.0.0.1:5432/clared` when Coolify forgets `DATABASE_URL`. Migrate then fails against localhost with an opaque connection error instead of "DATABASE_URL is required". `ENV DATABASE_URL=` in the Dockerfile is empty string, which is still unset-ish for the `if (!process.env.DATABASE_URL)` check (`""` is falsy — good); a whitespace-only Coolify value would not be.
**Fix:** Do not write `process.env.DATABASE_URL` in config. Let Prisma error. Keep the dummy only as a generate-time `ARG` in the Dockerfile `RUN` line.

### IN-03: `webview-data-url` remains process-wide

**File:** `apps/desktop/src-tauri/Cargo.toml:16-17`; `apps/desktop/src-tauri/tauri.conf.json:23-25`
**Issue:** Feature is on the `tauri` crate (comment documents login-only use). Main window `csp` is still `null` and has no `on_navigation`. Login allowlist now origin-keys `data:` to `login_init_url()` only (old WR-02/CR-01). Future `WebviewWindowBuilder` can still load `data:` without a second Cargo change.
**Fix:** Keep login as the only data-URL window. Do not add another `WebviewUrl::External(data:)` without the same allowlist.

### IN-04: `/health/ready` e2e does not assert Redis

**File:** `apps/backend/test/health.e2e-spec.ts:28-32`; `apps/backend/src/health/health.controller.ts:26-31`
**Issue:** Ready now pings Redis as well as Postgres. The e2e only checks status `200|503` and that the body matches `/postgres/`. A silent Redis check regression would still pass.
**Fix:** Expect `redis` in the JSON as well (`toMatch(/postgres/)` and `toMatch(/redis/)`).
