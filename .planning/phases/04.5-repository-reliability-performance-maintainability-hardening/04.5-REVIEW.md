## Warnings

### WR-01: Deploy SHA gate fails closed on Gotenberg (and any ready dependency)

**File:** `.github/scripts/coolify-deploy-nest.sh:167-172` (consumer); `apps/backend/src/health/health.controller.ts:36-50` (producer)
**Issue:** Post-deploy verification requires HTTP 200 from public `/health/ready` plus `.details.build.sha == SHA_TAG`. That endpoint runs postgres, redis, **gotenberg**, and build checks. Coolify has `GOTENBERG_URL` set on `clared-api-ghcr` (confirmed via env list). Live `GET https://clared-api.puzzlessdev.online/health/ready` currently returns `details.gotenberg.status=up` with no `build` key (old image). After this phase ships, a Gotenberg blip / auth / network failure during the ~2m poll window yields `poll_ok!=1`, triggers `rollback_changed`, and undoes an otherwise good API pin. Deploy success is incorrectly coupled to PDF infra.
**Fix:** Narrow the deploy probe to build identity + core deps only. Prefer one of:

```typescript
// health.controller.ts — dedicated deploy probe (example)
@Public()
@Get("build")
getBuild() {
  const sha = process.env.GIT_SHA?.trim() || "unknown";
  return { status: "ok", sha };
}
```

```bash
# coolify-deploy-nest.sh — poll /health/build (or /health + tag) instead of /health/ready
http_response=$(curl -sS --connect-timeout 5 --max-time 15 -w "\n%{http_code}" \
  "https://clared-api.puzzlessdev.online/health/build" 2>/dev/null || true)
ready_sha=$(printf '%s' "$ready_body" | jq -r '.sha // empty' ...)
```

Keep `/health/ready` for Uptime Kuma / ops; do not use it as the Coolify rollback gate.

### WR-02: Coolify and health curl calls have no timeouts

**File:** `.github/scripts/coolify-deploy-nest.sh:16-48`, `167-168`
**Issue:** `coolify_get`, `coolify_pin`, deployment polling, and the public health curl omit `--connect-timeout` / `--max-time`. A hung Coolify API or stuck TLS handshake blocks until the deploy job `timeout-minutes: 30`, then relies on TERM→EXIT rollback. That stretches half-pinned windows and delays fail-closed recovery.
**Fix:** Add timeouts on every curl:

```bash
curl -fsS --connect-timeout 5 --max-time 30 -X GET \
  "${COOLIFY_URL}/api/v1/applications/${1}" \
  -H "Authorization: Bearer ${COOLIFY_TOKEN}" \
  -H "Accept: application/json"

# health poll
curl -sS --connect-timeout 5 --max-time 15 -w "\n%{http_code}" \
  "https://clared-api.puzzlessdev.online/health/ready"
```

Use a slightly higher `--max-time` for POST `/deploy` if Coolify is slow to acknowledge, but keep it well under the job timeout.

### WR-03: Cancel / EXIT rollback path is untested

**File:** `.github/scripts/coolify-deploy-nest.test.sh:175-229`
**Issue:** Mock suite covers `health_fail`, `worker_deploy_fail`, and `success` only. Prior fix iteration added `rollback_on_exit` + INT/TERM→EXIT handlers specifically so GHA cancel/timeout does not leave a half-pin. That path has no assertion. A future edit can drop the EXIT trap or `deploy_succeeded` guard and CI still reports green.
**Fix:** Add a scenario that sets `changed_api=1` mid-run (or sends SIGTERM to the deploy script after the API pin stub) and asserts `pin:${API_UUID}:prev-api` appears and exit is non-zero. Example shape:

```bash
echo "test: SIGTERM after API pin rolls back"
export MOCK_SCENARIO="success"
# run script in background, kill -TERM after first API pin line appears in PIN_LOG
# assert rollback pin + non-zero exit
```
