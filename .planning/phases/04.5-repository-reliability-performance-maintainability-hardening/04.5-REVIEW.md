## Critical Issues

### CR-01: AJV gate uses `rg`; missing on GHA → silent false OK

**File:** `scripts/assert-ajv-zero-warnings.sh:11-12`  
**Issue:** Gate pipes tax-engine test output through `rg -q` / `rg -c`. GitHub-hosted Ubuntu 24.04 images do not install ripgrep ([Ubuntu2404-Readme](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md) — not in Tools or apt list). `ci.yml` `backend-unit` (line 216) runs this script with no install step.

Because the `rg` call is inside an `if` test, `set -e` does **not** abort on exit 127. Local reproduction with `PATH=/usr/bin:/bin`:

```text
bash: line 1: rg: command not found
ELSE_rc=127
SURVIVED
```

Result: CI prints `OK: zero AJV strict mode warnings` even when AJV would have warned — REL-03 is a no-op on GHA. Local machines with `rg` on PATH still enforce correctly, masking the gap.

**Fix:** Prefer portable `grep` (always present), or install ripgrep before the gate and fail closed if the matcher binary is missing:

```bash
# Option A — portable
if printf '%s\n' "$OUTPUT" | grep -F 'strict mode:' >/dev/null; then
  WARN_COUNT="$(printf '%s\n' "$OUTPUT" | grep -F -c 'strict mode:' || true)"
  echo "FAIL: found ${WARN_COUNT} AJV strict mode warning(s)" >&2
  exit 1
fi
```

```bash
# Option B — keep rg, fail closed if absent
command -v rg >/dev/null || { echo "FAIL: rg required" >&2; exit 1; }
```

### CR-02: Parallel push jobs share cancel-in-progress concurrency (regression)

**File:** `.github/workflows/backend-image.yml:70-72`, `141-143`, `211-213`  
**Issue:** `push-api`, `push-worker`, and `build` all use:

```yaml
concurrency:
  group: backend-image-build-${{ github.ref }}
  cancel-in-progress: true
```

GitHub concurrency allows only one running job per group; with `cancel-in-progress: true`, a sibling job starting in the same group cancels the in-progress one ([docs](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)). That undoes REL-04 parallel pushes and reintroduces the defect fixed in `3e47bcd` (workflow-level concurrency, no per-job group on push jobs). Commit `8b93622` removed workflow-level concurrency and re-added the shared job-level group — regression.

When one push job is cancelled, `build` (`needs: [deploy-script-test, push-api, push-worker]`) is skipped; GHCR may retain a half-published API or worker tag.

**Fix:** Restore workflow-level cancel for stale runs, and do **not** put `push-api` / `push-worker` in the same cancel-in-progress group. Example:

```yaml
concurrency:
  group: backend-image-${{ github.ref }}
  cancel-in-progress: true

jobs:
  push-api:
    # no job-level concurrency (or unique group without cancel)
  push-worker:
    # no job-level concurrency
  build:
    # optional: omit job concurrency; workflow-level already covers superseding runs
  deploy:
    concurrency:
      group: coolify-nest-deploy
      cancel-in-progress: false
```

If the intent of `8b93622` was only to avoid cancelling in-flight **deploys**, keep `coolify-nest-deploy` with `cancel-in-progress: false` and use a **separate** workflow-level group for build/push — never one shared cancel group across the two parallel push jobs.

### CR-03: `deploy-script-test` calls `uvx` without installing uv

**File:** `.github/scripts/coolify-deploy-nest.test.sh:304` (invoked from `.github/workflows/backend-image.yml:63-64`)  
**Issue:** After mock tests, shellcheck, and actionlint, the script runs `uvx zizmor@1.30.0 …`. Ubuntu 24.04 runners do not ship `uv`/`uvx` (absent from runner-images software list; no `astral-sh/setup-uv` or install step in `deploy-script-test`). With `set -euo pipefail`, missing `uvx` fails the job after mocks succeed. `build` needs `deploy-script-test`, so the whole image/deploy pipeline blocks.

**Fix:** Install uv in the job (preferred) or drop `uvx` from the CI-invoked script path:

```yaml
# backend-image.yml deploy-script-test
- uses: astral-sh/setup-uv@… # pin commit SHA
  with:
    version: "0.8.15" # or current pin
- name: Coolify deploy mock tests (REL-01)
  run: bash .github/scripts/coolify-deploy-nest.test.sh
```

Or split: mock/shellcheck/actionlint in CI; run `uvx zizmor` only where uv is guaranteed (local / separate lint workflow that already installs it).
