## Warnings

### WR-01: Coolify PATCH JSON built via unescaped string interpolation

**File:** `.github/scripts/coolify-deploy-nest.sh:27`
**Issue:** `coolify_pin` embeds `${IMAGE}` and `${tag}` directly in a JSON string. Values are workflow-controlled today (`github.repository`, 7-char SHA), but a registry name containing `"` or `\` would produce malformed JSON or alter PATCH semantics. `jq` is already required elsewhere in the script.
**Fix:**
```bash
payload=$(jq -n --arg image "$IMAGE" --arg tag "$tag" \
  '{docker_registry_image_name: $image, docker_registry_image_tag: $tag}')
curl -fsS -X PATCH "${COOLIFY_URL}/api/v1/applications/${uuid}" \
  -H "Authorization: Bearer ${COOLIFY_TOKEN}" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d "$payload" \
  -o /dev/null
```

### WR-02: Deploy mock tests not wired into CI

**File:** `.github/scripts/coolify-deploy-nest.test.sh` (no workflow reference)
**Issue:** REL-01 mock coverage (health-fail rollback, worker-before-API rollback order, token non-leakage, ShellCheck) only runs when invoked manually. No `.github/workflows/*` step calls `bash .github/scripts/coolify-deploy-nest.test.sh`. Changes to `coolify-deploy-nest.sh` trigger `backend-image` (build/push) via path filter but not the mock suite; deploy regressions can merge undetected until a manual run or production deploy.
**Fix:** Add to `zizmor.yml` actionlint step block or a dedicated `backend-image` pre-deploy check:
```yaml
- run: bash .github/scripts/coolify-deploy-nest.test.sh
```

### WR-03: Workflow cancel-in-progress can abort in-flight production deploy

**File:** `.github/workflows/backend-image.yml:45-47,285-320`
**Issue:** Workflow-level `concurrency` with `cancel-in-progress: true` cancels the entire prior run when a new push to `main` queues. That includes the `deploy` job while `coolify-deploy-nest.sh` is running. Runner cancellation sends SIGTERM; the script's `trap rollback_changed ERR` does not run on SIGTERM, so API may be pinned to a new tag while worker is not (or rollback may be incomplete). Deploy job concurrency `coolify-nest-deploy` / `cancel-in-progress: false` only serializes deploy jobs across runs; it does not protect against parent-workflow cancellation.
**Fix:** Split build and deploy into separate workflows (deploy triggered via `workflow_run` or reusable workflow with `cancel-in-progress: false`), or set workflow-level `cancel-in-progress: false` and rely on job-level groups for build jobs only.

### IN-02: Schema anyOf refactor incomplete on nullable fields

**File:** `packages/tax-engine/src/schema/clared-tax-rule-dsl-schema.json:55-58`
**Issue:** Seven union fields use `anyOf` per plan, but `effective_from`, `effective_to`, `threshold_amount`, and `threshold_currency` still use `"type": ["…", "null"]` arrays. Tests emit zero AJV warnings today; inconsistency may confuse future schema editors.
**Fix:** Optional consistency pass — e.g. `"anyOf": [{ "type": "string", "format": "date" }, { "type": "null" }]` for date fields.

### IN-03: Hygiene boundary test covers only two route files

**File:** `apps/desktop/src/__tests__/hygiene-boundary.test.ts:11-14`
**Issue:** Guard checks `entities.tsx` and `kunden.tsx` only. A new import of the deleted module in another route would not be caught. Low risk given prior zero-caller proof.
**Fix:** Extend `routeSources` to all `apps/desktop/src/routes/*.tsx` or add one repo-wide assertion.

### IN-04: backend-unit runs tax-engine tests twice

**File:** `.github/workflows/ci.yml:215-216,228`
**Issue:** `assert-ajv-zero-warnings.sh` runs `pnpm --filter @clared/tax-engine test` (full Jest suite), then `backend-unit` runs `pnpm --filter @clared/tax-engine exec jest` again. Redundant CI time; not a correctness defect.
**Fix:** Drop the standalone jest step at line 228 and rely on the assert script, or change the assert script to compile-only / stderr-scan without re-running tests.
