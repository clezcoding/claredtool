## Critical Issues

### CR-01: AJV gate calls `rg` but GHA runners lack ripgrep

**File:** `scripts/assert-ajv-zero-warnings.sh:11-12`  
**Issue:** REL-03 gate pipes test output through `rg -q` and `rg -c`. GitHub-hosted `ubuntu-24.04` images (current `ubuntu-latest`) do not ship `rg` — confirmed against [actions/runner-images Ubuntu2404-Readme](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md) (no ripgrep in installed software or apt list). `ci.yml` line 216 runs this script in `backend-unit` with no prior install step. Any backend/tax-engine/shared change triggers a CI failure unrelated to AJV warnings.  
**Fix:** Prefer portable `grep` (available on all GHA runners), or add an explicit install step before the gate:

```bash
# Option A — portable (no extra CI step)
if printf '%s\n' "$OUTPUT" | grep -q 'strict mode:'; then
  WARN_COUNT="$(printf '%s\n' "$OUTPUT" | grep -c 'strict mode:' || true)"
  echo "FAIL: found ${WARN_COUNT} AJV strict mode warning(s)" >&2
  exit 1
fi
```

```yaml
# Option B — keep rg, install in ci.yml backend-unit before the gate
- name: Install ripgrep
  run: sudo apt-get update && sudo apt-get install -y ripgrep
```

### WR-01: Deploy mock test duplicates curl stub (~140 lines)

**File:** `.github/scripts/coolify-deploy-nest.test.sh:33-123` and `203-278`  
**Issue:** The happy-path test rewrites the entire `curl` stub inline instead of reusing the first stub or a shared fixture file. The two copies already diverge in behavior (e.g. worker POST handling). Future deploy-script changes risk updating one stub and not the other, weakening regression coverage without a failing test.  
**Fix:** Extract one `curl` stub heredoc to a variable or `fixtures/curl-stub.sh` sourced by both the default PATH setup and the happy-path override; or parameterize `MOCK_SCENARIO` in the single stub.
