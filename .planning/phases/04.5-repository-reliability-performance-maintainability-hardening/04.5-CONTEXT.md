<decisions>
## Implementation Decisions

### Coolify deploy maintainability
- **D-01:** Extract inline deploy bash from `backend-image.yml` **only if** research proves identical runtime behavior, unchanged secret/env boundaries, and ShellCheck-clean readability gain — otherwise keep inline.
- **D-02:** Any extracted script must be locally testable: ShellCheck plus mock/dry-run coverage for `curl`/`jq` deploy and rollback paths.
- **D-03:** Keep current fail-closed deploy order (API → worker) with `trap ERR` rollback — no simplification. — **Reversibility:** costly — production deploy safety from Phase 04.4 D-23/D-25.
- **D-04:** Keep post-deploy API verification: Coolify tag poll **and** public `https://clared-api.puzzlessdev.online/health/ready` HTTP 200 before worker deploy.

### Desktop bundle / code-splitting
- **D-05:** Act on Vite chunk warnings only when a chunk remains **> 500 kB** after splitting (measure gzip, not raw bytes only).
- **D-06:** Split strategy order: **first** verify whether existing dynamic imports (`main.tsx` → `sentry`/`updater`; `app-shell.tsx` → `debug-panel`) actually produce separate chunks; only then consider route-level or `manualChunks` changes.
- **D-07:** Total gzip bundle size may increase by at most **+5%** as a tradeoff for splitting; reject splits that exceed this.
- **D-08:** No UI or routing redesign — code-splitting changes only.

### Tax-engine AJV hygiene
- **D-09:** Fix strict-union warnings by correcting **test fixtures** and the schema SSOT (`docs/clared-tax-rule-dsl-schema.json`) — do **not** loosen Ajv options (`strictUnion`/`strictTypes`) or suppress warnings.
- **D-10:** Leave production `packages/tax-engine/src/store.ts` Ajv configuration unchanged; scope is test-run hygiene only.
- **D-11:** Do not change tax logic, rule priorities, collision semantics, or `evaluate()` behavior. — **Reversibility:** one-way — tax semantics are locked since Phase 03 (D-13/D-15).
- **D-12:** Acceptance: **zero AJV warnings** in `packages/tax-engine` test runs (local + CI).

### CI performance, repo hygiene, docs
- **D-13:** Pursue CI walltime improvements across **all three** handoff baselines with equal priority: PR `desktop-rust` (~7:29), `main` Rust CodeQL (~8:58), backend-image+deploy (~5:00). Each proposed change still needs before/after walltime evidence and must not weaken security or coverage — but no single baseline is deprioritized upfront.
- **D-14:** Repo-hygiene discovery: **codebase knowledge graph first**; grep/text search only for configs and string literals.
- **D-15:** Dead-code removal only with **proven zero callers**; public/exported modules require a boundary test before deletion.
- **D-16:** Docs alignment scope: `.planning` + ops docs for **04.4 post-merge facts** and manual founder tasks (required checks, Secret Scanning, Push Protection) — use addenda, do not rewrite immutable PLAN/SUMMARY history.
