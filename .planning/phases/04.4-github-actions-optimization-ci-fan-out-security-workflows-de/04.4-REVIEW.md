## Warnings

### WR-01: Worker Coolify status glob treats `running: unhealthy` as success

**File:** `.github/workflows/backend-image.yml:325-330`
**Issue:** Poll uses `case "$STATUS_LC" in *running*)`. Coolify values like `running: unhealthy` or `running: starting` match, so a not-ready worker sets `poll_ok=1`, skips rollback, and deploy succeeds.
**Fix:** Match healthy running only; reject `unhealthy`:

```bash
STATUS_LC=$(printf '%s' "$STATUS" | tr '[:upper:]' '[:lower:]' | tr -d ' ')
case "$STATUS_LC" in
  running|running:healthy)
    poll_ok=1
    break
    ;;
esac
```

### WR-02: API `/health/ready` poll can succeed on the previous revision

**File:** `.github/workflows/backend-image.yml:300-313`
**Issue:** After PATCH+POST, the script polls the public URL until HTTP 200. It does not verify Coolify finished swapping or that the live process matches `SHA_TAG`. A still-healthy old container can pass before a broken new image lands.
**Fix:** Poll Coolify until `docker_registry_image_tag` equals `SHA_TAG` and `/health/ready` is 200, or use the same healthy-running status check as WR-01 for the API app UUID.

### WR-03: Leftover `type=ref,event=branch` can publish a `:latest`-shaped GHCR tag

**File:** `.github/workflows/backend-image.yml:82-84`
**Issue:** D-24 removed `type=raw,value=latest`. Metadata still has `type=ref,event=branch,enable=${{ github.ref != 'refs/heads/main' }}`. `workflow_dispatch` is not limited to `main`; dispatch from a branch named `latest` publishes `ghcr.io/<repo>:latest`. Arbitrary branch tags can also be pushed to the production registry (deploy stays `main`-only).
**Fix:** Delete the `type=ref,event=branch` line. Optionally gate `build` with `if: github.ref == 'refs/heads/main'`.

```yaml
tags: |
  type=sha,prefix=sha-,format=short
```

### WR-04: FaynoSync upload treats HTTP ≥400 as success if the body contains `already exists`

**File:** `.github/workflows/desktop-build.yml:274` and `:321`
**Issue:** `test "$HTTP_CODE" -lt 400 || grep -q 'already exists'` accepts any error body containing that substring (e.g. 500 HTML).
**Fix:**

```bash
if [ "$HTTP_CODE" -lt 400 ]; then
  :
elif [ "$HTTP_CODE" = "409" ] && grep -q 'already exists' /tmp/fayno-mac.json; then
  :
else
  echo "FaynoSync upload failed HTTP ${HTTP_CODE}"
  exit 1
fi
```

### WR-05: Deploy rollback swallows `coolify_pin` failures

**File:** `.github/workflows/backend-image.yml:272-279`
**Issue:** `rollback_changed` calls `coolify_pin ... || true`. On deploy failure the job fails, but a failed rollback is indistinguishable from success in logs (`outcome: rollback attempted`). Production can remain pinned to a bad new tag while the workflow only signals generic failure.
**Fix:** Remove `|| true` on rollback pins (or capture exit codes, fail the job if rollback fails, and echo explicit per-app rollback status to `$GITHUB_STEP_SUMMARY`).

## Info

### IN-01: `${{ }}` still interpolated inside `run:` on signed desktop

**File:** `.github/workflows/desktop-build.yml:69` and `:198`
**Issue:** Ternary still expanded in shell scripts. Values are bounded (`staging` / `production` / `inputs.target`); workflow is not PR-triggered — not external injection. Pattern zizmor env-wrap avoids.
**Fix:** Move ternary to `env:` and reference `"$TARGET"` / `"$FS_ENV"` in the script.

### IN-02: Analysis workflows omit Harden-Runner

**File:** `.github/workflows/gitleaks.yml:24`, `.github/workflows/zizmor.yml:39`, `.github/workflows/codeql.yml:56`
**Issue:** `ci.yml`, `desktop-build.yml`, and `backend-image.yml` start with `step-security/harden-runner` (`egress-policy: audit`). Gitleaks, Zizmor, and CodeQL do not. No extra secrets on those jobs; audit coverage inconsistency only.
**Fix:** Add the same SHA-pinned Harden-Runner step first if uniform egress audit is desired.

### IN-03: `cosign-installer` downloads Cosign `v3.0.6` at runtime

**File:** `.github/workflows/backend-image.yml:172-174`
**Issue:** Installer action is SHA-pinned; `cosign-release: v3.0.6` still fetches a GitHub Release blob on a privileged job (`packages: write`, `id-token: write`).
**Fix:** Pin a verified checksum if supported, or vendor the binary.

### IN-04: `rust-toolchain.toml` triggers CodeQL but does not enable Rust analyze

**File:** `.github/workflows/codeql.yml:18` vs `:74-78`
**Issue:** Workflow `on.push` / `pull_request` paths include `rust-toolchain.toml`. `detect` rust filter does not. A toolchain-only change starts the workflow, sets both language outputs false, and skips analyze.
**Fix:** Add `rust-toolchain.toml` to the rust paths-filter block.

### IN-05: FaynoSync response bodies are echoed to workflow logs

**File:** `.github/workflows/desktop-build.yml:273` and `:320`
**Issue:** `cat /tmp/fayno-mac.json` / `fayno-win.json` after upload. Token stays in `Authorization` header; derived JSON fields may not be masked.
**Fix:** Log HTTP code plus a jq projection (`version`, `id`) instead of the raw body.
