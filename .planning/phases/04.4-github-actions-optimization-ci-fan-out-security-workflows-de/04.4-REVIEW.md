## Critical Issues

### CR-01: Health/status poll failure skips rollback (ERR trap bypass)

**File:** `.github/workflows/backend-image.yml:333-336`, `356-358`
**Issue:** After `trap rollback_changed ERR`, API and worker poll failures use explicit `exit 1`. Bash does not invoke `ERR` on intentional `exit` — only on failing commands. When `changed_api=1` (or both flags set) and the poll fails, the job exits without calling `rollback_changed`, leaving Coolify pinned to the new broken tag. Violates D-23 (“on failure roll back already-changed targets”).
**Fix:** Call rollback explicitly before exiting, or replace `exit 1` with a failing command inside the trap scope:

```bash
if [ "$poll_ok" != "1" ]; then
  echo "Health poll failed for clared-api"
  rollback_changed
  exit 1
fi
```

Apply the same pattern for the worker status poll at lines 356-358. Optionally remove `trap - ERR` only after both polls succeed.

**File:** `.github/workflows/backend-image.yml:29`, `44-49`
**Issue:** D-26 limits builds to `main` push + `workflow_dispatch`, but dispatch is not gated to `main`. A maintainer dispatching from a feature branch still pushes `sha-<7>` images to GHCR (deploy stays `main`-only). Low risk; registry clutter only.
**Fix:** Optional `if: github.ref == 'refs/heads/main'` on the `build` job, or document intentional branch-dispatch for image experiments.
