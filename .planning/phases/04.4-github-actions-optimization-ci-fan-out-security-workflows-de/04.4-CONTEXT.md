**Gathered:** 2026-09-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Implement `docs/claredtool-github-actions-optimierungsauftrag.md` in full: cut GitHub Actions fan-out and runner cost without weakening the `ci` aggregator, updater signing, or Coolify deploy safety.

**In scope:** Brief phases 1–8 remainder after quicks `260828-5c8` (CI-OPT-01–03) and `260828-mn3` (CI-OPT-04–06). Path filters on `main`, draft-PR gating, `desktop-web` / `desktop-rust` split, consolidated `backend-test` with walltime guard, Gitleaks/Zizmor/Actionlint/CodeQL workflows, signed desktop only on `v*` + `workflow_dispatch`, Dependabot lockstep/limits, backend-image/deploy cleanup, checkout/digest/permissions hardening, step summaries. Required check still named exactly `ci`.

**Out of scope:** Changing GitHub Branch Protection / Environments / Secret Scanning via API (manual checklist only). Production dispatches and `v*` tags during implementation. Nightly desktop builds. `pull_request_target`. `workflow_run` for desktop/backend deploy. `egress-policy: block` on Harden-Runner. New reporting SaaS. GitHub-hosted Prisma migrate against prod (brief 6.6). Product/UI work. Phase 5 PDF/audit/offline.

<decisions>
## Implementation Decisions

### Non-negotiable (from brief + prior phases)
- **D-01:** Required aggregator check stays named exactly `ci`. Do not skip the whole `ci` workflow with workflow-level `paths` (pending-check trap).
- **D-02:** No `pull_request_target` for PR code. No `workflow_run` for desktop or backend deploy.
- **D-03:** Pin every external Action to a full commit SHA. No moving tags (`@v4`, `@main`, `@latest`).
- **D-04:** Signed desktop jobs keep `package-manager-cache: false`. No pnpm/Rust/`node_modules`/build-output caches on the signed path.
- **D-05:** `GITHUB_TOKEN` least privilege; unmentioned scopes fall to `none`. No secrets in logs, step summaries, or artifacts.
- **D-06:** Do not auto-change GitHub settings, Branch Protection, or Environments. End with a manual checklist. Do not trigger production deploys or signed releases during implementation.
- **D-07:** Carry forward 04.2: FaynoSync is updater SSOT (D-05/D-29 there); channel `stable` only — no Nightly in 4.4 (04.2 D-07); Windows NSIS + macOS `.app.tar.gz` updater artifacts (04.2 D-27/D-28).

### Pflicht-Checks
- **D-08:** Add `.github/workflows/gitleaks.yml`: `push` only `main`, `pull_request` including drafts, optional `workflow_dispatch` for full-history scans. No weekly Gitleaks schedule. `fetch-depth: 0`, `persist-credentials: false`, concurrency with `cancel-in-progress: true`.
- **D-09:** After merge, founder adds **required** status check named `gitleaks` (separate from `ci`). No admin bypass. Cursor does not edit Branch Protection.
- **D-10:** Gitleaks findings **fail** the job (not `continue-on-error`). Upload SARIF to the Security tab; `security-events: write` only on that upload job/step.
- **D-11:** Add `.gitleaks.toml` empty (or defaults-only). Allowlist entries only with a proven false positive plus comment. No blanket fixture-path excludes.
- **D-12:** Manual checklist: enable GitHub Secret Scanning **and** Push Protection (repo is public; free). Does not replace Gitleaks.
- **D-13:** CodeQL and Zizmor/Actionlint stay **not** required while they are path-selective (skipped workflow = pending required check). Zizmor workflow is path-filtered; Actionlint runs in the same workflow, not a third PR-visible workflow. CodeQL: weekly full JS/TS+Rust; push/PR language-split jobs; draft PRs skip analyze jobs.

### Desktop-Release
- **D-14:** Remove automatic signed Windows/macOS build + FaynoSync publish from `main`. Triggers: `v*` tags (production) and `workflow_dispatch` only. — **Reversibility:** costly — every `main` UI push currently signs two platforms; putting it back re-opens the cost/secret surface.
- **D-15:** `v*` tag = production publish. `workflow_dispatch` defaults to staging; production dispatch remains an explicit override (rebuild without a new tag). Tags and manual release runs are not cancelled by branch concurrency.
- **D-16:** On `v*` tags: create a GitHub Release with installers (MSI + DMG). FaynoSync still gets updater artifacts (NSIS `.exe`+`.sig`, macOS `.app.tar.gz`+`.sig`). Production **dispatch** (no tag) uploads FaynoSync only — no GH Release.
- **D-17:** Replace `windows-latest` / `macos-latest` with pinned GitHub-hosted generations after a manual staging test on **both** platforms. Exact labels from current GitHub docs (research). Comment the chosen generations in the workflow.
- **D-18:** Actions artifact retention: staging 3 days, release 14 days. GH Release assets stay until the release is deleted. `compression-level: 0` for already-compressed binaries; `if-no-files-found: error`.
- **D-19:** Staging matrix `fail-fast: true`. `v*` tag matrix `fail-fast: false`. Do not install `rustfmt`/`clippy` on the release toolchain.

### Backend-Image & Deploy
- **D-20:** Prefer one BuildKit Bake for API + worker (shared graph/cache). If Bake makes tags, labels, or cache less clear or less safe: keep two `build-push` steps and document why. Identity stays immutable `sha-<7>` (API) and `sha-<7>-worker`. `linux/amd64`. `provenance: false` and `sbom: false` until Coolify attestation-index issues are gone.
- **D-21:** Introduce Trivy (not present today). One HIGH/CRITICAL scan only if the workflow **proves** API and worker RootFS layers match; otherwise fail or scan both. If the comparison costs more than the second scan, keep both scans. Never drop coverage for a theoretical saving.
- **D-22:** Do **not** add a GitHub-hosted Prisma migrate job. API container `CMD` (`prisma migrate deploy && node dist/main.js`) stays the only migrator. Worker does not migrate. Coolify `deploy` job stays. Document that multi-replica later needs exactly one external migrator (brief 6.6) — do not activate it now.
- **D-23:** Collapse the serial deploy matrix into one ordered job: API then worker. Capture previous tags; log both deploys; on failure roll back already-changed targets to previous tags. Keep `concurrency.group: coolify-nest-deploy` with `cancel-in-progress: false`.
- **D-24:** Stop pushing GHCR `latest`. Deploy and humans use SHA tags only. — **Reversibility:** costly — anything still pulling `:latest` will break; Coolify already pins SHA.
- **D-25:** After Coolify deploy, HTTP-check API `/health` or `/health/ready`; failure triggers D-23 rollback. Worker has no public host — do not invent a public worker health URL. Kuma remains the standing monitor.
- **D-26:** Keep `vars.COOLIFY_IMAGE_DEPLOY` kill switch. Image builds stay `main` + `workflow_dispatch` only — no PR images to GHCR.
- **D-27:** Clean redundant `backend-image.yml` path entries (`apps/backend/Dockerfile`, explicit tax-schema path) per brief 6.1. Keep the root lockfile trigger until an importer-accurate filter is proven.

### CI fan-out (brief 1–2, still incomplete vs Ist-Stand)
- **D-28:** Remove the `github.ref == 'refs/heads/main' ||` exception on expensive `ci.yml` jobs. `changes` + aggregator `ci` always run; skipped children are OK; `failure`/`cancelled` fail the aggregator.
- **D-29:** Draft PRs: `pull_request` types include `ready_for_review`. Heavy jobs skip on drafts; `changes` + aggregator still succeed. `ready_for_review` starts path-selective heavy jobs.
- **D-30:** Split `desktop` filter into `desktop-web` vs `desktop-rust` (do not use `apps/desktop/**` as the web filter). New jobs `desktop-web` and `desktop-rust`. Consolidate `backend-unit` + `backend-e2e` into `backend-test` unless walltime rises >25% vs the slower of the two (then keep split, share setup via local composite). Filtered `pnpm install --frozen-lockfile`. Local `.github/actions/setup-pnpm-ci` only if ≥2 identical Node/pnpm setups remain; signed desktop must not use that cache-on composite.
- **D-31:** Unify PR/analysis concurrency to `group: ${{ github.workflow }}-${{ github.ref }}` + `cancel-in-progress: true` on `ci`, `codeql`, `gitleaks`, `zizmor` (labeler optional). Never cancel production deploys, tags, or manual releases. Add short `run-name`s (purpose + ref/PR or deploy target). No untrusted PR titles in shells.

### Dependabot, delivery, validation
- **D-32:** Dependabot per brief table: npm weekly open-PR cap 5; Cargo weekly cap 3; GitHub Actions / Docker / Docker Compose monthly cap 3; stagger times. Add Nest major lockstep group for co-updated `@nestjs/*`. Keep security updates on. Keep `glib` ignore and Node-25 block unless the underlying break is proven fixed.
- **D-33:** Ship as **one PR with seven logical commits**: (1) trigger/concurrency, (2) CI job split + filtered installs, (3) security workflows + Actionlint, (4) desktop-release, (5) Dependabot, (6) backend-image/deploy, (7) hardening/summaries/test reports. Linear history; no squash of those seven.
- **D-34:** Validate locally first (YAML parse, Actionlint, Zizmor, ShellCheck, relevant tests). GitHub scenario table (docs-only, draft, ready-for-review JS/TS, Rust-only, backend-only, workflow-YAML, docs-only `main`, etc.) only after an **explicit user push OK**. No production dispatch and no `v*` tag during this phase. Staging desktop dispatch + runner-pin test is **after** merge/approval, not inside the implementation PR.
- **D-35:** Step summaries via `$GITHUB_STEP_SUMMARY` (changed areas, skipped jobs, image tags, deploy/rollback) with no secrets. Test reports: native JUnit/coverage if the existing framework already supports it; upload verbose reports only on `failure()`; retain 3–7 days; no new reporting SaaS; extra reporter dependency only with a separate justification.
- **D-36:** Leave `labeler.yml` / `sync-labels.yml` behavior as-is (brief phase 9). Harden-Runner stays on signing/deploy jobs; `egress-policy: block` is out of this phase. Pin CI service images (Postgres/Redis) by digest once research has verified current official digests; keep the readable tag in a comment; Dependabot must still be able to bump them.

### Claude's Discretion
- Exact GitHub-hosted runner generation labels (`windows-2022` vs `2025`, `macos-14` vs `15`) after docs + staging test (D-17).
- Bake vs two-step after a real Bake attempt (D-20).
- Trivy Action SHA, RootFS-compare method, and whether one vs two scans wins on measured cost (D-21).
- Actionlint version/image digest; CodeQL `build-mode` for Rust only if current official docs support it.
- `/health` vs `/health/ready` for D-25 (use whichever the API already exposes as the deploy gate).
- Whether `.github/actions/setup-pnpm-ci` is warranted after the split (D-30).
- Nest major-group package glob within `@nestjs/*`.
- Step-summary wording and JUnit retention inside the 3–7 day window.
- Postgres/Redis digest values (must be fetched, never invented).

</decisions>
