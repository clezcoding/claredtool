## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, field-error gap |
| sm | 8px | Compact element spacing, list row gap, chip/banner inner gap, sidebar `p-2` |
| md | 16px | Default element spacing, page `p-6`, create-panel field stack, header gap |
| lg | 24px | Section padding, card spacing |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing, empty-state column |

Exceptions: Interactive header/picker/Anlegen/Neue-Rechnung controls use 44px (`min-h-11`) minimum hit target (not strictly 4-multiple). Do not enlarge Phase 1 nav rows or „+ Position“ to 44px. Line-item hover-X stays 14px icon, visible on hover/focus (Phase 1 D-21). Phase 1 live `py-1.5` (6px), `gap-3` / `p-3` (12px) are **not** in this scale — snap: „+ Position“ `px-4 py-2`; identity card `grid gap-4`; `LineItemCard` `p-4`. Do not promote 6px or 12px into the scale.

**Source:** Phase 1 UI-SPEC 8-point scale + Phase 2 44px exception. No new scale. Radius: `--radius` / `--radius-md` = 8px. Lists, panels, inputs, pickers, cards use `rounded-md` (8px). Do not introduce a new radius.

## Visual Hierarchy

**Signed-in invoice (this phase focal point):** Invoice heading (20px semibold) at top of the left panel, with the invoice picker in the same header row. First visual anchor after login (last edited draft, D-17). Tax rail is secondary (right, no accent fill). **Entities / Kunden:** Screen heading (20px) + „Anlegen“ in the header. List is the primary scan. Create/detail panel opens **under** the list in the same `max-w-xl` column (D-01) — not a dialog, not a split inspector, not a new route. **Signed-out / login / chip / banners:** Unchanged Phase 2. Silent-boot success no longer lands on the Phase 1 sample invoice — it lands on the last edited draft or the first-run empty (D-17 replaces Phase 1 D-22 and Phase 2 silent-boot „filled sample“).

### Entities (ENT-01)

- Header: Heading „Entities“ + „Anlegen“.
- „Anlegen“ **always visible**. Enabled iff `entity.create`. Otherwise disabled with hint „Nur Inhaber können Entities anlegen.“ (D-04). Server still 403s if called; that 403 is not the primary UX.
- List: one row per entity, Body 14px, name as primary text. Click selects the row and opens the **read-only detail panel** under the list (Phase 1 D-29 slot).
- „Anlegen“ (enabled) opens the **writable create form in the same panel slot**, replacing detail. Clicking a row while create is open switches back to that row’s detail. No dialog, no `/entities/new` route (D-01).
- Create fields, stacked `gap-2` (8px) inside `Card` `max-w-xl` (D-19):
  1. Name — required, `Input`
  2. Land — required, Combobox (searchable). Placeholder „Land wählen“.
  3. Rechtsform — required, Combobox. Disabled until Land is set. Placeholder „Zuerst Land wählen“. Options = that country’s catalog only (D-03). Never a worldwide flat dump, never free-text.
  4. Adresse — required, `Input`
  5. USt-IdNr. — visible **only when Land is an EU country**. Required in that case. Hidden otherwise (not an empty optional).
- Submit control: none named „Speichern“. Creating persists on explicit primary inside the panel: the panel’s accent button label is **„Entity anlegen“** (one-shot create, not draft autosave). After success, the new row is selected and the panel switches to read-only detail.
- Do not add email/notes. Do not add entity delete UI (`entity.delete` stays unused). Do not add tax-override chrome.

### Kunden (ENT-01)

- Same list + panel pattern as Entities. Heading „Kunden“.
- „Anlegen“ always visible. Enabled iff `kunde.write`. Otherwise disabled with hint „Keine Berechtigung zum Anlegen von Kunden.“
- Customer **always belongs to one entity** (D-02). Create form fields:
  1. Entity — required Combobox of entities the user can read. Placeholder „Entity wählen“.
  2. Name — required
  3. Land — required Combobox
  4. Adresse — required
  5. USt-IdNr. — EU-only, same rule as entity
- No legal-form field on customers (D-19). No email/notes (mock does not show them).
- Panel submit: **„Kunden anlegen“**. After success, select the new row + read-only detail (name, address, country, USt-IdNr. if present, parent entity name).
- Do not add customer delete UI.

### Rechnung canvas (INV-01)

**Header row** (`flex items-start justify-between gap-4`):
- Left: Heading „Rechnung“ + Combobox invoice picker (D-08) showing the current number (or „Neue Rechnung“ while unnumbered). Searchable. Not a sidebar item.
- Right cluster (`flex items-center gap-2`): autosave status (Label 12px) then „Neue Rechnung“.

**„Neue Rechnung“** (D-07): enabled iff `invoice.write`. Opens an **empty form** (no copy of last draft, no Phase 1 sample). Previous drafts remain in the picker. Disabled hint when missing write: „Keine Berechtigung zum Anlegen von Rechnungen.“

**Autosave (D-05):** no Save button. After **600ms** pause in typing (discretion default; same pause as tax evaluate, D-09). Status Label 12px:

| State | Copy | Color |
|-------|------|-------|
| In flight | Speichert… | `text-muted-foreground`; optional 16×16 Spinner beside the text. `prefers-reduced-motion: reduce`: no spin |
| Success | Gespeichert | `text-muted-foreground` |
| Failure | Speichern fehlgeschlagen. Eingaben bleiben sichtbar. | `text-destructive` |

Failure does not blank the form and does not block typing. Retry on the next debounce. No toast.

**Without `invoice.write`:** picker and fields are read-only; autosave is off; status hidden; „Neue Rechnung“ disabled with the hint above. Tax rail still evaluates if `tax.evaluate` (viewer/auditor).

**Identity card** (new, under header; `Card` + `grid gap-4` — snap from Phase 1 live `gap-3`):

| Field | Control | Rules |
|-------|---------|-------|
| Rechnungsnummer | read-only `Input` | Assigned by backend (year + counter). Placeholder until first successful autosave: „Wird vergeben…“. User cannot edit. |
| Datum | `Input` | Existing |
| Fällig | `Input` | Existing |
| Entity (seller) | Combobox | Required. Placeholder „Entity wählen“. Changing seller filters Kunden and, if currency still equals the previous entity default, updates currency to the new entity default (D-20). |
| Kunde | Combobox | Required. Disabled until Entity is set. Placeholder „Zuerst Entity wählen“. Options = customers of that entity only (D-02). |
| Währung | Select | Defaults from seller entity; changeable per invoice (D-20). Options: EUR, USD, AED, plus the entity default if missing from that list. Trigger is secondary (not accent). |

**Line items:** compact cards (Phase 1 D-17–D-21) with `p-4` (snap from live `p-3`). Four fields stay visible. This phase they are **editable `Input`s** (same chrome as header inputs). Netto is computed read-only. Document-level tax only — no per-line tax on the card. „+ Position“ at list bottom (`px-4 py-2`). Hover/focus X deletes the line immediately (no confirm dialog; copy is the accessible name „Position löschen“).

**Empty form vs first-run illustration:**
- **Zero invoices (first-run):** reuse `apps/desktop/public/empty-state-hero.png` above the empty form in the left pane (`max-w-xl`, `rounded-md`, `alt=""`). Heading + body from Copywriting empty rows. **Remove** „Beispielrechnung anzeigen“. Tax rail and PDF peek stay hidden while the illustration is showing (Phase 1 E6). The empty identity card + empty line list + „+ Position“ sit under the copy so the user can start without a second CTA.
- **Neue Rechnung while drafts exist:** no illustration. Empty identity card + empty line list. Tax rail visible with em-dash placeholders until the first successful evaluate.
- After the first persistable keystroke (or first successful autosave), hide the illustration if it was showing and reveal the tax rail.

**PDF peek:** unchanged Phase 1 staged paper under the rail. Do not wire real PDF. Do not remove. Click still opens `/pdf` staged view.

### Live tax (TAX-01)

- Re-evaluate automatically **600ms** after relevant fields change (D-09). No „Steuer berechnen“ button. Desktop never embeds the engine (D-10).
- Invoice **rail shows exactly four fields** as `dt` keys (canonical, not translated): `invoice_tax_rate`, `reverse_charge_flag`, `legal_reference`, `applied_rule_id` (D-12). Heading remains „Live Steuerberechnung“.
- `/tax` shows all nine TaxDecision fields (Phase 1 list) from the **same** evaluate result, live.
- Before the first successful evaluate: labels visible, values em dash `—`. Never show `SAMPLE_INVOICE` tax numbers on the signed-in path.
- On evaluate failure (D-11): **keep the last good TaxDecision** (or em dashes if none). Show a small error **in the rail** (and the same line on `/tax`): Body 14px / 400 / `text-destructive`, wraps. Do not blank the rail. Do not block typing. No modal. Next debounce retries. Optional rail text button „Erneut versuchen“ (`text-primary` underline, not a filled CTA — reserved accent text-link) re-fires evaluate immediately.
- No tax override UI (D-16). `tax.override` unused in UI.

### Country → legal form (D-03)

Two sequential Comboboxes, never one 200-row dump. Country Combobox is searchable (German display names, ISO stored). Legal-form Combobox is searchable **within the selected country**. Changing country clears legal form. Combobox empty copy: „Kein Land passt zur Suche.“ / „Keine Rechtsform passt zur Suche.“

Reuse Phase 1 `empty-state-hero.png` (2688×1520) for first-run invoice empty (discretion). **Do not** generate a new illustration this phase. Do not reuse `login-gate-hero.png` here. Missing file: keep heading, body, and empty form; do not swap in the login-gate art.
